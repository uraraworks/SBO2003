# サーバー回帰テスト

性能改善の前後で、送信バイト列・キャラ状態・経路探索の結果が変わらないことを確かめる。

- 実行して golden と比べる: `tests/server/compare.sh`（「一致」と出れば OK。BENCH 行は計測値）
- 出力だけ見る: `tests/server/run.sh [出力ファイル]`
- golden を作り直す（挙動を意図して変えた時だけ）: `tests/server/run.sh /tmp/x.txt && grep -v -e '^BENCH' -e '^\[' /tmp/x.txt > tests/server/golden.txt`

現在の golden の実データは非公開リポジトリの `e50b862`（2026-11-07）。最新版のデータでは NPC 数・地形などが違うため、無関係な差分が出る。既存 golden を確かめる時は、この版を一時領域に展開して `SBO2003_PRIVATE_DIR` で指定する（非公開リポジトリの作業ファイルは変えない）。

```sh
mkdir -p /tmp/sbosvr-golden-fixture
git -C "$(tools/server/find-data.sh --repo)" archive e50b862 Release/SBODATA | tar -x -C /tmp/sbosvr-golden-fixture
SBO2003_PRIVATE_DIR=/tmp/sbosvr-golden-fixture bash tests/server/compare.sh
```

AO/AP は受付で説明と姿一覧を同時に受信→姿選び→全員への準備完了会話→外の入口で入場の順に実行する。説明の優先順位と末尾の入力待ち除去、一覧を出してから30秒での締切、旧クライアントの BEGIN が一覧を再送・再開せず締切も延ばさないことを確認する。AO では2分の受付期限、集合待ち、未受付・未選択の入場拒否、移動・離脱・切断での受付取消も確認する。`TMPDIR` を指定するとテストのデータコピー・ビルドログ・比較結果をその場所に置く。

時刻と乱数は固定、通信は mock_net.js、実データは非公開リポジトリ SBO2003-private の Release/SBODATA のコピー（元は書き換えない。探し方は tools/server/find-data.sh）。

AO の共有地図では、入場時に実際に送られた地形を、本体から抽出したブラウザ受信処理（CRC・圧縮展開・通知サイズ）と探索記録処理に渡す。地形→キャラ情報→探索送信の順序を再現し、圧縮あり・なしの差分が記録と仲間の位置へ反映されることを確認する。2人の組の探索差分・仲間の位置・別空間への非配信・ソロの非共有・重複の抑止・不正な報告の拒否・累積記録の再送・移動時だけの位置更新を確認する。

AO では姿選び中（未選択・一部選択済み）と受付済みの別マップ移動を共通の移動処理・周期処理で検出し、組全員の取消・仲間への通知・選択窓の閉鎖・戻った後の入場拒否を確認する。選択中の切断でも仲間へ通知し、外の入口からの正規入場では取り消さない。
