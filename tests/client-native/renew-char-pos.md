# キャラ座標一覧・灯りの受信更新をまとめる検証

```sh
python3 tests/client-native/run-renew-char-pos.py
source ~/emsdk/emsdk_env.sh
CXX=em++ CXXFLAGS='-O2 -fno-strict-aliasing' python3 tests/client-native/run-renew-char-pos.py
```

SDK のキャッシュを書き込めない環境では、キャッシュを一時領域へコピーして `EM_CACHE` を設定する。
ゲームのビルドには組み込まない。生成ソースと実行ファイルは一時ディレクトリに作り、終了時に消す。

`renew-char-pos-old.inc` は変更前の RenewCharPosInfo。本体の新実装が dirty フラグの解除以外は同一であることをスクリプトでも検査する。
灯り計算・視界記録・橋判定・削除・3種類の受信関数・パケットの詰め直し・文字列・CRC・DrawMapLight を実行時に本体から抽出する。
旧受信関数は、更新要求の呼び出しだけを旧実装の即時呼び出しに戻して生成する。通信送信と UI 表示は記録するスタブで置き換える。
ホストでも DWORD は Wasm と同じ32ビット。演算の融合・fast-math は使わない。

1,128受信列（ランダム768＋画面・マップ境界360）、各24通知（合計27,072通知）を旧・新に同じ順で再生する。
50/100/150/200キャラ、追加・更新・削除・不明キャラ・別マップ・消滅通知、向き変更と途中の参照、入力だけを変えるマップ通知相当の操作も含む。
画面とマップの端、マップ光源0/16個、描画上限32光源、マスク上限48個、半径0/最大、光源の重なり、キャラ灯りの最大半径、壁・カウンター、明るい/暗い/視界/隠す範囲・範囲の重なりを組み合わせる。
灯り描画は時刻を固定入力として与え、本体の式で異なるゆらぎ位相を再現する。

各通知後にキャラ情報（文字列アドレスのみ正規化）・配置数・未受信一覧・オブジェクト・送信記録を完全比較する。
参照の直前と最後に行別一覧の全要素・明るさ全289バイト・灯りマスクの全バイトと順序・隠す範囲・探索済み記録を完全比較する。
さらに同じ背景へ本体の DrawMapLight を実行し、544×544画素のアルファと描画範囲外を含む全バイトを比較する。ハッシュ比較ではない。
作業用 g_pMapDarkTmpPos は出力に含めない（明るいマップでは元実装も前回値を残す）。描画側は参照していない。
画像素材を使うマップ全体の描画は行わないが、行別一覧・キャラ状態・灯りを含む描画入力が完全一致し、描画処理は変更していない。

ホストと Wasm/Node.js の両方で1,128受信列すべて一致、不一致0。

更新1回はウォームアップ後に200回×5組の中央値、20通知分の比較は30フレーム×5組の中央値（旧・新の計測順を交互にする）。受信解析・画像描画の時間は含めない。
この環境の事前ホスト計測は、明るいマップが約0.001〜0.002ms、暗いマップ（壁による遮光あり）が約0.09〜0.47ms/回。暗いマップで効果があると判断した。
Wasm の20通知/フレームの計測例（ms）：

| 条件 | 旧 | 新 |
| --- | ---: | ---: |
| 50キャラ・明るい・マップ光源0 | 0.008497 | 0.000503 |
| 50キャラ・暗い・壁あり・マップ光源0 | 1.954065 | 0.097707 |
| 200キャラ・暗い・壁あり・マップ光源16 | 9.855401 | 0.493657 |

## 参照経路と更新時点の確認

- `g_aCharPos` の読み取りは DrawBridgeOverHead・DrawCharLine。
- `g_pMapDarkTmp` の描画参照は DrawScreenMOVE・DrawMapViewFog・DrawMapLine・DrawCharLine・DrawWeather。IsMapDarkHidePos 経由では DrawCharLine・DrawChar2・DrawChar3 も読む。
- GetLightMask・IsMapHideShowTile は DrawMapLight から読む。
- これらはすべて WM_PAINT → OnPaint → DrawScreen から呼ばれる。WndProc は受信以外のメッセージを処理する前に FlushCharPosInfo を呼ぶので、キュー途中の描画・入力・切断にも保留を残さない。MainLoopWeb の UpdateWindow 直前にも反映する。
- 受信関数に上記キャッシュの読み取りはない。キャラ通知内の衝突・橋判定はマップとキャラ情報を直接使う。ただし、別の通知で入力だけが変わる時も旧実装と同じ更新時点を保つため、3種類以外の受信通知の実行前に反映する。
- TimerProc の開始前と、そこで保留受信列を再生した直後に反映する。削除・爆弾設置・管理編集などの既存 RenewCharPosInfo は即時更新のままで、dirty も解除する。
- 視界モードは RenewMapViewSeen が途中で見たマスを永続記録するため、従来どおり即時更新する。自キャラ未確定時と Windows 版も即時更新する。

連続する3種類の通知は原則1回にまとまる。途中の描画・別通知・削除などの確定点があれば必要な回数だけ更新し、厳密な「どんな場合も1フレーム1回」には制限しない。

release ビルドは成功（SDK キャッシュの書き込み制限を避けて `EM_CACHE=/tmp/sbo-em-cache` を使用）。
`cd tests/client && node pixels.js ../../out/web/dist` は、HTTP サーバーの待ち受けが環境に拒否され `listen EPERM 127.0.0.1` で実行できなかった。依存パッケージは既に導入済み。
