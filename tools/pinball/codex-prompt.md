# Codex への指示：SBO2003 ピンボールの盤の絵を描く

あなたは「SBO2003」（ドット絵の 2D オンラインゲーム）のサブゲーム「ピンボール」の盤の絵を、
ピクセルアートで描きます。絵は 2 枚の PNG（背景・部品シート）です。**このファイルの指示と、同じフォルダのテンプレートだけで作業できます。**
パスはすべて**リポジトリのルート**（Windows では `C:\AI\work\projects\SBO2003`、Mac では clone した `SBO2003` フォルダ）からの相対パスです。
コマンドは、ルートで実行してください。Windows の PowerShell ではパスの `/` はそのままで動きます（`python` を使う。Mac は `python3`）。

## ゴール

- `pinball_bg.png`（背景 160×448）と `pinball_parts.png`（部品 128×96）を作る。
- ゲームの他の絵（マップパーツ・キャラ）と並んでも浮かない「SBO らしい」見た目にする。
- **当たり判定はコードの図形で決まっていて変えられない**。絵は当たり判定のガイドにぴったり合わせる。

## 手順

### 1. 見本を読む（SBO らしさを掴む）

見本は `SboGrpData/grp/` の PNG です（ゲームが実際に使う絵）。画像として開いて見てください（中身は 16 ドットのマスを 2 倍に拡大して表示します）。

- `map01.png` 〜 `map05.png`：マップパーツ（地面・壁・レンガ・床・家具）。壁・石・床の質感と縁取りの見本。**一番大事**
- `char01.png` 〜 `char16.png`：キャラ（人物の縁取り・色の少なさの見本）
- `obj3232_01.png`：32×32 のオブジェクト（宝箱など）
- `efc01.png`〜`efc06.png`：エフェクト・吹き出し
- `system.png`：メニュー・アイコン・数字の部品（UI の色づかい）
- `SubGame_bomb.png`：同じ「サブゲーム」の先輩の絵（爆弾ゲーム）。サブゲームの絵の雰囲気の見本

見るポイント：暗い色の 1 ドットの縁取り／1 つのもので 3〜5 色（明・中・暗＋縁）／ベタ塗り＋くっきりした陰（ぼかし・グラデーション・半透明は無い）／少し暖色寄りの落ち着いた色。
ピンボールの舞台は、マップ上に置かれた「石造りの遊戯台」の設定です（床は石レンガ・木の家具のある町）。壁は石・木・金属のリベットのような、町の建物と同じ質感にしてください。

### 2. テンプレートを用意する

テンプレート一式は tools/pinball/template/ にあります（`pinball_bg_guide.png`・`pinball_bg_empty.png`・`pinball_parts_guide.png`・`pinball_parts_empty.png`・拡大版・`layout.json`）。コンパイラが無い環境でもそのまま使えます（make_art_template.py で作り直すのは座標を変えた時だけ）。
コードの座標が変わった時だけ、ルートで作り直します（Python 3・Pillow・g++ か clang++ が必要。Pillow は `pip install pillow`）。

```sh
python3 tools/pinball/make_art_template.py -o out/pinball-art
```

- `*_guide.png`：当たり判定の輪郭（壁＝水色・バンパー＝橙・ターゲット＝黄・フリッパー＝桃・穴＝赤・球＝緑）と 16 ドット格子と番号を、薄く重ねたもの。**下敷き。仕上げの PNG には含めない**。
- `*_empty.png`：ガイド無しの空版（透明＝黒のインデックスカラー PNG）。**この上に描く**（またはガイドを下のレイヤーにして、描いたレイヤーだけを書き出す）。
- `*_x3.png`・`*_x6.png`：人が見る用の拡大。
- `layout.json`：座標・半径の一覧（全部ドット。盤の左上が (0,0)、y は下向き）。

### 3. 描く（仕様の要点）

詳しくは `docs/pinball-art.md`（必ず読む）。要点：

**共通**
- **透明は黒 (0,0,0)**。絵の中で黒を使わない（縁取りは (16,16,32) くらいの暗い色）。
- 半透明・アンチエイリアス・ぼかし・グラデーションは使わない（ドットはくっきり）。
- 8 ビットのインデックスカラー PNG・256 色まで。目安は背景 48 色・部品 32 色以内。
- **2×2 ドットの太いピクセル**で描く（背景は 80×224、部品は 64×48 で描き、最近傍で 2 倍に拡大して保存）と SBO になじむ。
- 輪郭は 1 ドット（拡大後は 2 ドット）の暗い縁取り。

**`pinball_bg.png`（160×448）**
- 盤全体を (0,0)–(160,448) に描く。画面は 160×224 の窓が上下に動いて映すので、上端〜下端まで途切れなく描く。
- 壁・アーチ・斜め壁・床・レーンの仕切りを、ガイドの水色の線に合わせる。**壁の「球に見える側の縁」をガイドの線の上に置き、厚みは盤の外側へ**描く。
- 盤の外（壁の外・アーチの外）は透明（黒）。
- バンパー・ターゲット・フリッパー・ボールは**背景に描かない**（部品シートの絵が重なる）。その位置は何も描かない（床の模様だけ）。
- 文字・得点・「GAME OVER」は描かない（ゲームが描く）。
- 穴（フリッパーの軸の間）は暗い口にする。打ち出しレーン（右の細い縦のみち）に細い溝・ばねの雰囲気を足してよい。

**`pinball_parts.png`（128×96）**：ガイドの番号どおりにセルへ描く。
1. ボール（16×16。半径 4 の球を中心 (8,8) に。明るい金属）
2〜4. ターゲット（32×16。中心 (16,8)。長さ 16・太さ 4 の板。立っている／倒れて低く暗い／光る白っぽい）
5〜6. バンパー（32×32。中心 (16,16)。半径 9 の丸いキノコ形。ふつう／光る）
7〜8. 左フリッパー（48×48。軸 (12,24)。軸から長さ 28 で、7=下へ 30°・8=上へ 30° の姿。太さ 6 の丸い棒。軸に丸いキャップ）
- 右のフリッパーはゲームが左右反転で作る。左だけ描く。
- 空いた所は透明（黒）のまま。

### 4. 保存して形式を調べる

出力ファイル名（この名前のまま）：

- `pinball_bg.png`
- `pinball_parts.png`

作業フォルダ（例 `out/pinball-art/final/`）に保存し、ルートで確認する。

```sh
python3 tools/pinball/check_art.py out/pinball-art/final/pinball_bg.png out/pinball-art/final/pinball_parts.png --preview out/pinball-art/final/preview.png
```

`OK: ゲームが読める形です` が出るまで直す。`preview.png`（背景にガイドを重ねたもの）を開いて、壁・アーチ・斜め壁がガイドの線と合っているか見る。
Pillow で書き出す時は、`im = im.convert('RGB').quantize(colors=48, dither=Image.Dither.NONE)` のようにして**必ず P モード**で `im.save('pinball_bg.png')`（RGBA のままでは読めません）。

### 5. ゲームで確認する（ブラウザ版）

1. 2 つの PNG を `SboGrpData/grp/` に置く（同名の既存ファイルは無い）。**確認用の仮の絵はコミットしない**。
2. ビルドして起動する（Emscripten・Node.js が要る。`web/README.md`・`tools/server/` を参照）。
   ```sh
   tools/web/build.sh
   tools/server/build.sh
   tools/server/run.sh
   ```
   ブラウザで `out/web/dist/` のページを開く（`web/README.md` の手順）。
3. ピンボールの台（台詞が `@i` の NPC）の席に座り、S キーで始める。
   - 背景の壁がガイドどおりに球を受け止めているか（球が壁の絵の上を通って見えたり、手前で跳ねたりしないか）
   - ↓を押して離すと球が上へ打ち上がり、窓が上へ動いて上の絵が見えるか
   - バンパー・ターゲットの位置・光り方・倒れ方、フリッパーの向きと動き（左右）
   - 3 球で終了まで
4. 絵が出ずに図形（線・円）のままなら、PNG の形式か大きさが違う。`check_art.py` で調べる。

### 6. 渡すもの

- `pinball_bg.png`・`pinball_parts.png`（最終版）
- `preview.png`
- 確認（ブラウザ）のスクリーンショット 2〜3 枚
- 描いていて当たり判定（ガイド）に無理があった所があれば、メモ（コードは変えない）

## やってはいけないこと

- `common/` や `SboCli/` などのコードを変えない（絵だけ）。
- ガイドの色・番号・格子線を、仕上げの PNG に含めない。
- 黒 (0,0,0) を絵に使わない／半透明・RGBA・16 ビットにしない。
- 仮の絵をリポジトリにコミットしない。
