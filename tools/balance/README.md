# バランステスト用シミュレータ（PR2 の最初の一歩）

サーバー依存のない戦闘ループ `common/BattleSim.h`（header-only。式は `common/BattleCalc.h`）と、それを呼ぶ native CLI `battlesim.cpp`。emscripten 不要。

## ビルドと実行
```
g++ -std=c++11 -O2 -I. tools/balance/battlesim.cpp -o /tmp/battlesim
/tmp/battlesim [seed=1] [試行回数=1000] [敵の狙い方=0] [連携=1] < scenarios.tsv
```
出力（タブ区切り、1行目はヘッダ）: 名前 / 勝率% / 残HP%（勝った時の平均）/ 所要秒（勝った時の平均）/ 回復回数（全試行の平均）/ 判定 / 敵特技回数 / 敵回復回数（どちらも 1 戦あたりの平均）。
9 列目: 倒れた味方の人数（1 戦あたりの平均）。
判定: 余裕=勝率95%以上かつ残HP50%以上 / 互角=80%以上 / きつい=40%以上 / 無理。

## 入力（1行1シナリオ、タブ区切り24列＋敵の特技の1列＋追加の味方の1列、`#` で始まる行は無視）
| 列 | 内容 |
|---|---|
| 1 | 名前（表示用） |
| 2-15 | プレイヤー: Lv, 最大HP, 最大Mana, 攻撃力（力など＋武器）, 守備力（Damage に渡す値）, 素早さ, 武器byMin, 回復特技Mana（0=無し）, 回復量, 回復time, 攻撃特技Mana（0=無し）, 攻撃特技の平均ダメージ, 攻撃特技time, 攻撃特技が攻撃力＋値型か（1/0） |
| 16-24 | 敵: HP, 攻撃力, 守備力（Damage に渡す値）, 素早さ, 体数（最大4）, 開始距離（マス）, 敵が動くか（1=敵が気づいて近づく/0=動かずプレイヤーが歩く）, 気づく範囲, 近づく確率% |
| 25（省略可） | 敵の特技（下の「敵の特技」）。省略か `-` なら特技なし（従来と同じ結果） |
| 26（省略可） | 追加の味方（下の「味方が複数」）。省略か `-` なら 1 人戦（従来と同じ結果） |

方針: 満タン周回で通常攻撃（空振り5%・会心2%）、HP40%以下で回復特技、Manaがあれば攻撃特技。回復道具、ジャスト、遠隔、属性軽減、状態異常は未対応（連携は味方が複数の時だけ入る）。

## 味方が複数（パーティ戦）
`BattleSim::OneBattleParty(Player *味方, 人数, Enemy, rng, 狙い方, 連携)`（1〜4人、職業の組み合わせ自由）と、集計の `RunParty`。`OneBattle` / `Run` は「1 人のパーティ」を呼ぶだけで、1 人の時は乱数の引き方も従来と同じ（段階1〜4の雑魚・全段階のボス格 約700シナリオで、改造前の battlesim と勝率・残HP・所要秒・回復回数が完全一致することを確認）。
CLI は 26 列目に追加の味方を書く: 1 人 = `Lv,HP,Mana,攻撃力,守備力,素早さ,武器byMin,回復Mana,回復量,回復time,攻撃特技Mana,攻撃特技平均,攻撃特技time,AT型`（14 値、列 2〜15 と同じ並び）、複数人は `|` 区切り。列 2〜15 のプレイヤーが先頭（前衛）。特技の列が要らない時は `-`。
- 位置: 味方は全員同じ距離（一団）。近づく・歩くのも一団で動く。味方の攻撃は全員、生きている手前の敵の先頭へ（集中攻撃）。各自が自分のゲージ（素早さ）で行動する。
- 敵の狙い方（サーバーの `FindTarget` = 探索範囲で一番近いプレイヤー、に近い単純な規則）: 一直線で全員が同じ距離なので「最寄り」は並び順で決まる。
  - `0`（既定）: 並び順の先頭（前衛）。狙いは `dwTargetTblID` のように持ち続け、倒れたら生きている次の人に変える。
  - `1`: 狙い直す時（最初・倒れた時）に、生きている味方のうち現在HPが一番低い人。
  - 通常攻撃・敵の特技（攻撃魔法）ともに、その 1 人に当てる（範囲魔法の巻き込みは未対応）。
- 回復特技を持つ人（回復Mana が 0 でない）は、Mana が足りれば「HP が 40% 以下の味方（自分含む）のうち割合が一番低い人」を回復（1 人分）。いなければ攻撃特技・通常攻撃。1 人戦の「自分が 40% 以下なら回復」と同じ規則。
- 連携: `RenkeiCheck` と同じ。別の人が同じ敵へ当ててから **2 秒未満**（`RENKEI_TIME`）で当てたらダメージ **130%**（`RENKEI_RATE`）。通常攻撃と攻撃特技の両方（特技は `平均ダメージ×130%`）。当てた時だけ記録する（空振りは記録しない）。同じ人が続けて当てても連携にならない。`連携=0` で無効（比較用）。
- 倒れた味方はそこで抜ける。全員倒れたら負け。勝ちの時の残HP% は味方全員の残HP合計/最大HP合計。
- 未対応: 範囲攻撃の巻き込み、味方同士の位置関係・距離、蘇生、回復道具、Mana 回復、敵が味方ごとに別の距離にいる状況。

## 敵の特技と回復
本番の `ChooseEnemyMagic` などの流れを入れてある（式は `common/BattleCalc.h` の `ChooseEnemyMagic` / `MagicDamageHpDown` / `MagicDamageHpDownAT` / `MagicDamageHpDownRate` / `MagicHealAmount`。乱数を引く順番は旧実装と同じで、`tests/server/battle_calc_test.cpp` が確かめる。サーバー側はまだ置き換えていない）。
- 敵は行動の番ごとに、まず特技のくじ。16 枠から 1 つ引き、空き枠なら通常攻撃。HP が 30% 以下なら先に 50% で回復枠を優先して選ぶ。
- 回復は、自分（周囲・画面内の特技なら仲間も）のHPが 70% 未満の時だけ。HP満タンや 70% 以上では引き当てても使わず、通常攻撃になる。離れている時（遠くから近づく間）は回復しない。
- 攻撃魔法は、目の前では使える。離れている時は、気づいて近づいている敵が 1 間隔後に 1 回だけくじを引き、前方=1〜射程マス・周囲=射程内・画面内=7マス以内なら撃つ（外れたら、殴る・撃つまで引き直さない。本番の `s_mapTry` の通り）。動かない敵（戦闘1）は殴られるまで狙いが無いので撃たない。
- ダメージ: HP減少=基本値−魔法防御/2（標準プレイヤーの魔法防御は 0）、HP減少(攻撃力)=敵の攻撃力＋基本値−プレイヤー守備/2、HP減少(率)=今のHPの率−魔法防御/2、回復=基本値（最大HPまで）。属性軽減と連携は入れていない。
- 敵は Mana を使わない（本番も敵は消費しない）。特技の「time」（詠唱の硬直）も敵には無いので、行動の間隔は通常攻撃と同じ。
- 未対応の効果（毒・眠り・召喚・加速・攻撃/守備アップ・隠れる・蘇生・明かり・帰還など）は、枠は引かれて行動は使うが何も起きない（種別 99）。置く魔法（種別 4/7）は子の魔法が上の効果なら 1 回分として数える（残って何度も当たる型は過小評価）。
- 列の形: 16 枠を `;` で区切り、空き枠は空文字、あれば `種別,基本値1,基本値2,発動種別,使用対象,射程`（本番の magic 表の byType, wData1, wData2, byTargetType, byTarget, byTargetArea）。例: `1,5,8,1,1,2;2,20,30,0,0,0;;;;;;;;;;;;;;`
- 変換は `tools/balance/enemyskill.py`（simdata.json の `enemies[].skills` を読む。`dexbuild/prep.py` が本番の magic 表から作る。`--refresh` で自動、手で足すなら `python3 -I dexbuild/prep.py <dex か simdata.json> <fetch したフォルダ> <出力>`）。無視した種類は report.md の (4) に出る。

## 注意
- 乱数は `std::mt19937`（seed 付き）を、0 以上の `long` を返す関数オブジェクトで包んで BattleCalc に渡している。`unsigned` のまま渡すとマイナスのダメージ計算が符号なしになって壊れる（サーバーの genrand は符号付き）。
- ゲージ時間・敵の行動間隔は `BattleCalc::GaugeTime` / `EnemyTurnTime`。SboSvr/SboCli はまだ旧実装のまま（置き換えは golden に影響するので別PR）。

## JS 試作との突き合わせ
```
python3 tools/balance/simdata2tsv.py simdata.json [段階=1] [体数=1] [開始距離] > /tmp/sc.tsv
/tmp/battlesim 1 20000 < /tmp/sc.tsv
node sim.js --stage 1 --n 20000     # JS 試作側（sbo2003-balance-sim）
```
JS 試作は `r()*100 > 66`（34%）、会心でも武器の減少値を引く点が BattleCalc（33%・会心は引かない）と違う。この2点を JS 側で揃えると段階1の雑魚88件の勝率差は最大0.3%。

## レポート生成（report.py）
battlesim を 1 プロセスにまとめて呼び、Markdown を 1 ファイル出す（約 1 万シナリオで 15 秒ほど）。
```
python3 tools/balance/report.py [--simdata simdata.json] [--out report.md] [--runs 1000] [--seed 1]
    [--hp-override 魔法使い:1=8,2=13,6-15=+5] [--refresh] [--only 1|2] [--detail 敵ごと.tsv]
```
- 既定の入出力は `/mnt/project-files/_work/sbo2003-balance-sim/` の `simdata.json` / `report.md`。`/tmp/battlesim` は無ければ（または古ければ）自動でビルドする。
- `--refresh`: 本番を読んで作り直す（環境変数 `SBO2003_AI_KEY` と本番ホストへの通信が要る。読むだけ）。`dexbuild/` の fetch.py → build_dex.py（図鑑 dex.json）→ prep.py（simdata.json）を順に呼ぶ。
- (1) 段階×職業×雑魚/ボス格（1体・3体）の勝率・残HP・所要秒・判定。標準プレイヤーは段階の目安Lv・店売り最強装備。
- (2) Lv1〜15 の職業別 最大HP・守備力・攻撃力・Mana、雑魚から受けるダメージ、耐えられる秒数、倒す秒、Mana切れまでに倒せる数、種込み（HP+25・Mana+20）・結晶込み（HP+120）の別表、魔法使いのまとめ。Lv→相手の段階は report.py の `stage_for_lv`。
- (4) 敵の特技（攻撃魔法・回復）を入れる前（特技なし）と後（既定）で判定が変わった敵を末尾の (4) に出す。無視した種類の一覧もここ。`--no-enemy-skills` で特技を全部外して (1)(2) を出せる（前の数字の再現用。その時 (4) は出ない）。
- (3) `--hp-override 職業:Lv=値,…`: 職業のLv別最大HPを一時的に置き換えて (1)(2) を再計算し、勝率の差分を末尾に付ける。値は数値で置き換え、`+N`/`-N` で加算、`6-15=30` で範囲指定、職業名は次の `職:` まで引き継ぐ。データは書き換えない。
- 同じ入力行は 1 回だけ計算するので、変えていない職業は差分が 0 になる（乱数のぶれが出ない）。

## BattleSim.h の修正（レポート作成中に発見）
敵の次の攻撃時刻が `t`（今の時刻）のままで、敵が 50ms ごとに殴っていた。サーバーは殴った時刻を `dwLastBattle` に記録して 1 間隔後なので `t + 敵の行動間隔` に直した。短い戦闘（数秒）ではほぼ影響しないが、HP の多い敵・長期戦で勝率が大きく下がっていた。上の JS 試作にも同じ誤りがあり、突き合わせは直前の版の話。

## 目標チェック（goal-check）
目標（Masakazuさん 2026-11-24）: (1) 雑魚1体は全職業が1人で普通に倒せる（暫定: 勝率90%以上）。(3) ボス格は2〜3人で挑む想定で、2〜3人の代表編成なら勝率が高め（暫定70%以上）、1人なら低め（暫定40%以下。0%でよい）。
```
python3 tools/balance/report.py --goal-check [--goal tools/balance/goal.json] [--goal-out goal-check.md] [--runs 1000] [--seed 1]
    [--target-rule 0|1] [--no-renkei] [--simdata simdata.json]
```
- 基準・パーティ編成・段階の重みは `tools/balance/goal.json`（`zako_solo_win_min` / `boss_party_win_min` / `boss_solo_win_max` / `parties` / `stage_weight` / `sensitivity` / `boss_override`＝設計上のボスなので目標チェックだけボス格扱いにする敵の名前）。暫定の数字なのでここだけ書き換えて再実行する。既定の出力は `/mnt/project-files/_work/sbo2003-balance-sim/goal-check.md`。通常のレポートは出ない（`--goal-check` の時はこちらだけ）。数秒で終わる。
- 中身: 目標1の表（段階×職業、雑魚の勝率の平均／最低）、目標3の表（ボス格ごとに 1人×8職と代表編成の勝率）、外れの一覧、末尾に「直す候補リスト」（重さ＝外れ幅(pt)×段階の重み。重みは序盤ほど重い）。
- 判定の単位: 目標1は敵の種類ごと（1 種でも基準未満なら、その 段階×職業 が外れ。表には最低勝率を出す）。目標3は 2人・3人それぞれの代表編成の勝率の中央値が基準未満なら「勝てない」、1人は職業ごとに基準超過なら「簡単すぎ」。
- 「見立て」: 外れた組の標準プレイヤー（編成は人数別の中央の勝率のもの）で、1 項目だけ動かして再計算した勝率の変化（自分のHP×1.5・守備力×1.5・攻撃力×1.5（攻撃特技も）、敵の攻撃力×0.7・HP×0.7、敵の特技なし。簡単すぎの場合は逆向き）の上位 3 つ（5pt 以上）。「敵の特技なし」が効くなら敵の特技（回復・魔法）、「攻撃力」が効くなら火力不足、…と読む。乱数のばらつき（1000回で ±3pt 程度）がある。HP・守備・攻撃・特技の数字の事実（他職中央値との比）も添える。
- 注意: 標準プレイヤーは種・結晶・回復道具なし。ボス格は 1 体（`count=1`）、開始位置は雑魚と同じ規則（動かない敵は距離3）。連携・回復・狙い方は上の「味方が複数」の簡易ルールで、実際の戦いより単純（立ち回り・集中攻撃・ジャストは入っていない）。

## 序盤の高HPの敵の比較（early_boss.py）
段階1 プヨンクイーン・段階2 ぬめぬめ が目標1を満たさない問題の改善案（敵の弱体・経験値据え置き・職業側・店/特技の入手・ボス格扱い）を、simdata のコピーをメモリ上で書き換えて比べる。`python3 tools/balance/early_boss.py [--simdata …] > 表.md`。データは書き換えない。結果と見立ては sbo2003-balance-sim の early-bosses.md。
