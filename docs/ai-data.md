# AI から設定データを操作する（データ API・MCP）

管理者ウィンドウで編集している「設定データ」を、AI（Claude Code など）から読み書きできます。
サーバーに HTTP の API（`/api/data/*`）と MCP の入口（`/mcp`）があり、中身は同じです。
まとめて JSON ファイルに書き出したり、JSON から取り込んだりする時は [data-json.md](data-json.md) を見てください。

## 扱えるデータ

| 種類（kind） | 中身 |
| --- | --- |
| `magic` | 特技（魔法）情報 |
| `magicUser` | 特技を使える職業（職業の番号の一覧） |
| `equUser` | 装備できる職業（職業の番号の一覧） |
| `job` | 職業情報とレベルアップ情報（`levelUp`） |
| `stTmp` | ステータステンプレート（NPC・敵の能力のひな形） |
| `item` | アイテム情報（種別ごとの詳細は `detail`） |
| `maker` | 作り手（料理人・鍛冶屋など）。名前と台詞 3 つ（`szMsgTalk`・`szMsgDone`・`szMsgLack`）と種類（`byKind` 0=レシピ・1=鑑定屋）。NPC の台詞を `@c` + 番号 2 桁にすると開く |
| `affix` | 付与（接頭辞・接尾辞）の表（`docs/item-affix.md`）。名前・位置（`byPos`）・付く装備種別・割合/固定値/魔法防御・ランク・重み・売値の割合。`wID` は自動で振る |
| `itemDerive` | 付与の付いた派生アイテムの表（読むだけ）。`itemId`（16384+行）・`wBase`・`wPre`・`wSuf`・`byUnknown` |
| `recipe` | レシピ。作り手（`byMaker`）・できる物（`wItem`）と個数（`byCount`）・材料 4 種まで（`awMatItem`・`abyMatCount`）・手数料（`dwGold`）・並び順（`wSort`）・種類（`byKind`。0=普通 1=鍛える 2=付け替える。1・2 は付ける付与 `wAffix`・普通の装備も対象 `byAllowPlain`・対象の装備種別 `wEquMask`。`docs/recipe.md`） |
| `quest` | ギルドの仕事依頼。名前・説明・報酬・段の数（`byStepCount`）・段ごとの目的（`goals`）・依頼を受けた人とパーティにだけ見えるNPC（`npcs`）。NPC の台詞を `@g` + ギルド番号 2 桁にすると、その人に話すと一覧が開く |
| `flag` | キャラのフラグ（ずっと残る印 1024 個と数値 128 個）に付ける名前の表。名前・種類（`byKind` 0=印・1=数値）・番号（`wNo`）。管理用でプレイヤーには出ない |
| `talk` | 会話データ。会話セット番号（`wID` 1〜999）ごとに最大 16 行（`lines`）。NPC の台詞を `@t` + 番号（例 `@t012`）にすると、話した人のフラグとレベルで台詞を出し分ける |
| `story` | 思い出の本のシナリオ。クリアしたミニシナリオをキャラごとにやり直す。名前・説明・状態・並び順・クリアした印（`wClearFlag`）・前のお話（`wPrevStory`）・やり直す時に戻すもの（印の範囲 `awFlagFrom`/`awFlagTo`・数値 `abyNum`・依頼 `awQuest`）・取り上げる持ち物（`awTakeItem`）・戻す宝箱（`awTakeChest`）・やり直した回数の数値（`byCountNum`）・コマンドの「目的」に出す「いまの目的」（`goals`）。NPC の台詞を `@r` にすると開く。消せない（`byState` 0 で止める） |
| `flagGroup` | フラグのグループ。印・数値の番号の帯（`bands`。1 グループ 16 本まで）にメイン名（`szName`）を付け、「ルシー-3（103）」のようにメイン-サブで管理する層（番号は変わらない。例：ルシー＝印 100〜139＋300〜319）。同じ種類で帯の重なりは不可。`flag` の記録に計算した `group`・`sub` が付く（読むだけ）。消すのは `byState` 0 |

セーブデータの残りも読み書きできます。**プレイヤーのキャラと預かり所（`leave`）だけは読むだけ** です。

| 種類（kind） | 中身 | 書き込み |
| --- | --- | --- |
| `char` | キャラ全員（プレイヤー・NPC）。能力・持ち物・装備・位置、NPC の台詞（`szNpcSpeech`）、巡回ルート（`route`）、転職前の職業で覚えていた特技（`jobMagic`）など。`isPlayer`・`online` でプレイヤーか・ログイン中か分かる | 保存される NPC だけ（下の「NPC」） |
| `map` | マップの情報・暗くする範囲（`darkAreas`）・イベント（`events`）・お店（`shops`）・メッセージ（`messages`）・アイテム配置（`items`） | できる（`darkAreas`・`events`・`shops`・`messages` は配列で丸ごと置き換え。`items` は読むだけ。大きさの変更・マップの追加はできない） |
| `mapParts` | マップパーツ（マス目に入る番号）の表示・当たり判定・アニメのコマ（`anime`） | できる（追加もできる。消せない） |
| `efc` | エフェクト情報（アニメのコマ `anime`） | できる（追加もできる。255 個まで。消せない） |
| `comEfc` | 吹き出し情報 | できる（99 個で固定なので追加はできない） |
| `leave` | 預かり所（キャラの `dwLeaveID` がこの番号） | 読むだけ |
| `subGame` | 爆弾ゲーム・迷路・ダンジョン・戦場ゲーム・すごろくの設定 | `detail` の項目。迷路は追加・止める（`byType` 0）もできる（下の「迷路」。ほかの種別の変更・追加・すごろくのマスは管理者ウィンドウで） |

マップのマス目（パーツの番号・フラグ・屋根）は `sbo_map_tiles`（`/api/data/tiles`）で 2 次元の配列として読めます（1 回最大 128×128）。
書き換えは `sbo_map_tiles_set`（`/api/data/tiles/set`）で、左上 `(x, y)` とパーツ番号の 2 次元配列 `parts` を渡します（下見 → 確定、履歴に残り戻せる）。
管理ページの「マップ確認」の編集モードで「サーバーへ反映」した変更も、同じ `tiles` の履歴（by は「管理ページ」）に 1 件で残り、同じように元に戻せます。

### マップの暗くする範囲（`map` の `darkAreas`）

地上から階段で洞窟へ降りるマップのように、マップの一部だけ暗くしたい時に使います（明るさ `byLightLevel` が 1 以上のマップだけ効きます）。

- `darkAreas` は `{"x1", "y1", "x2", "y2", "dark"}` の配列（8 個まで）。四角の左上〜右下のマスで、右下の列・行も含みます。
  `dark` は 1=暗くする・0=暗くしない・2=明るいが壁や扉の向こうは見えない（省くと 1）。2 は舞台裏の部屋のように、中は全部明るく見せて外は隠したい時に使います（マップの明るさが 0 でも効きます）。範囲の中は壁や家具まで全部見え、中にいる間は範囲の外は見えません。範囲の境目では灯り（自分の灯り・光源・光るパーツ）が1マス目（境目の壁・カーテン・扉）で止まるので、外からは部屋の壁や扉までは見えて奥は見えず、外の光源がカーテン越しに中を照らすこともありません。中から見えるのは、その範囲の四角の中だけです（範囲が重なった所も、四角の中なら見える）。範囲には部屋のまわりの壁まで入れてください。隣の部屋との間の壁は、両方の範囲に入るように重ねておくと、どちらの部屋からも見えます。範囲は 1 つずつ別の部屋として扱います（並べても隣の範囲は見えない）。範囲には床だけでなくまわりの壁も入れてください。
- 空なら今までどおりマップ全体が明るさの設定どおり。「暗くする」範囲が 1 つでもあれば、どの範囲にも入らない所は明るくなります。
  「暗くしない」「壁の向こうは見えない」範囲だけなら、入らない所は暗いまま。範囲が重なった所は、配列の後ろの範囲を優先します。
- 例（地上は明るく、洞窟の四角だけ暗く、その中の一角は明るく）: `[{"x1":0,"y1":40,"x2":75,"y2":89,"dark":1},{"x1":0,"y1":40,"x2":10,"y2":45,"dark":0}]`
- ゲーム内の管理者ウィンドウ（マップ→マップ情報→「明るさ・灯り・見え方の設定...」）でも一覧で足したり並べ替えたりできます（一覧の下ほど優先）。座標はゲーム画面のクリックで拾えます（1回目で左上、2回目で右下）。

### マップの光源（`map` の `lights`）

パーツが無くても、マップの決まったマスから照らします（天井から吊るした灯りなど）。光るパーツ（`mapParts` の `byLight`）と同じく、暗いマップで、そのマスから `range` マスまで照らし、壁や閉まった扉の向こうは照らしません。

- `lights` は `{"x", "y", "range", "power", "flicker", "warm"}` の配列（16 個まで）。`range` は 1〜7（必須）。
  `power` は強さ 1〜100%（省くと 100。小さいほど薄暗い）、`flicker` は 1=ゆらめく・0=ゆらめかない（省くと 1）、`warm` は 1=炎のような暖色・0=色を変えない（省くと 0）。
- 管理者ウィンドウの同じ小窓（マップ情報→「明るさ・灯り・見え方の設定...」）の「光源」でも足せます。位置はゲーム画面のクリックで決められ、編集中はゲーム画面にすぐ反映されます（「OK」で送信、「キャンセル」で元に戻す）。
- 光源は画面の少し外にあっても、照らす範囲が画面に入っていれば効きます。
- 「見える範囲」（`byViewRange`）のマップでは、光源が照らす所も見えます（カウンターの中など、壁や家具の向こうでも灯りがあれば見える）。
- マップのフラグ `byFlg` に 128（キャラの灯り無し）を足すと、暗いマップで自分の灯りが無くなり、光源で照らした所だけが見えます（自分の足元だけうっすら見える。明かりの道具を持っていれば照らす）。バーのように薄暗くしたい時は「暗闇」(8)と一緒に使うと、壁や扉の向こうも照らしません。

### マップごとのパーツの灯り（`map` の `partsLights`）

光るパーツ（`mapParts` の `byLight`）の範囲は全マップ共通です。たいまつなどの範囲をこのマップだけ変えたい時に、パーツ番号ごとの上書きを置きます。

- `partsLights` は `{"wParts", "byLight"}` の配列（8 件まで、丸ごと置き換え）。`wParts` はパーツ番号（0〜パーツ数-1）、`byLight` はこのマップでの灯りの範囲 0〜7 マス。**0 にするとこのマップではそのパーツは光りません**。同じ `wParts` を 2 回書くとエラーです。
- 書いていないパーツは今までどおり、全マップ共通の `byLight` で光ります。`[]` を送ると上書きを全部消します。
- 例: `"partsLights":[{"wParts":824,"byLight":2},{"wParts":830,"byLight":0}]`（パーツ 824 はこのマップでは 2 マス、830 は光らない）。
- 管理者ウィンドウの同じ小窓（マップ情報→「明るさ・灯り・見え方の設定...」）の「パーツの灯り（このマップだけ）」でも、一覧と追加・変更・削除で編集できます（編集中はゲーム画面にすぐ反映。「OK」で送信、「キャンセル」で元に戻す）。

### 印で変わるマス・宝箱・リサイクル箱（`map` の `swaps`）

マップの特定のマスのパーツを、**その人の画面だけ**別のパーツに差し替えます。見た目と通れるか（当たり判定）の両方が変わります。ほかの人の画面は変わりません。
用途は 3 つあり、1 行ごとに `kind` で選びます（`kind` は 0・1・2 の数のほか、`"flag"`・`"chest"`・`"recycle"` の文字でも書けます）。差し替えるのはマスのパーツ（`sbo_map_tiles` の `parts`。パーツは 1 マス 1 つだけ）です。1 マップ 64 行まで、`swaps` は配列で丸ごと置き換えです（履歴・元に戻す・しおりに乗ります）。

- `kind` 0 ＝ **印で変わる**（物語のしかけ用。依頼を終えた人にだけ橋がかかる・崩れた壁が通れる、など）。`{"kind":0,"x","y","wFlag","byCmp","wParts"}`。
  キャラの印（0〜1023。会話データ・依頼・思い出の本と同じ印）を見ます。`byCmp` 0（省くと 0）＝「印が立っている時」に `wParts` に差し替え、1＝「印が立っていない時」に差し替え。印が動く所（会話・依頼・管理者ウィンドウの印の変更など）で、その人の画面だけすぐ変わります。
- `kind` 1 ＝ **宝箱**。`{"kind":1,"x","y","wParts","wGiveItem","szMsg","szMemo","wChestNo"}`。
  印は使わず、キャラごとの「開けた宝箱の記録」（宝箱番号 0〜2047 のビット列）を使います。`wParts` は開いた後のパーツ。記録がまだ無い人が**目の前のそのマスを調べる**（Sキー）と、`wGiveItem`（item の番号。0 か省略＝品なし）を渡して記録を立て、`szMsg`（UTF-8・95 バイトまで。省略可）を出して、その人の画面だけ `wParts` に変わります。記録のある人が調べても何も起きません。
  持ち物がいっぱいで渡せない時（会話データの渡す品と同じ決まり。持ち物がいっぱいなら預かり所へ、大事な物は大事な物の欄へ。どちらもだめなら「持ち物がいっぱいで受け取れませんでした」）は記録を立てず、また調べると開けられます。依頼の品など大事な物の扱いも会話データの渡す品と同じです。
  `szMemo` は管理用のメモ（例「ルシー 港の倉庫の奥」。UTF-8・63 バイトまで）で、プレイヤーには出ません。
  **宝箱番号（`wChestNo`）は全マップ通しで重ならない 0〜2047 の番号**です。足す時に省くと空き番号が自動で振られます（指定もできます。ほかの宝箱と重なると断ります）。**消した宝箱の番号は使い回しません**（古いキャラの記録のビットが残っているため。マップごとに「使った最大番号+1」を覚えていて、自動で振る番号はそれより後ろ）。直す時は、`get` で読んだ `wChestNo` を付けたまま書き戻してください（番号を省くと新しい番号が振られ、前の番号の宝箱を開けた人は新しい宝箱を開けていない扱いになります）。思い出の本のやり直しでは、シナリオの `awTakeChest` に指定した宝箱の記録だけ戻ります（指定しない宝箱は戻らず、宝は一度きり。「思い出の本（`story`）」の節を参照）。
- `kind` 2 ＝ **リサイクル箱**（`docs/recycle.md`）。`{"kind":2,"x","y","wParts","szMemo","wBoxNo"}`。
  使えるのはこれだけで、印・開けた記録・`wGiveItem`・`szMsg` は使えません（付けると断ります）。マップのパーツ（`sbo_map_tiles`）は**閉じた箱**のままにしておき、`wParts` に**開いた箱の絵**のパーツを入れます。
  プレイヤーが**目の前のそのマスを調べる**（Sキー）と、その人の画面だけ `wParts` の絵になり、「入れる・もらう・やめる」の窓が開きます。窓を閉じると閉じた絵に戻ります（開いて見えるのは調べた本人だけ）。窓を開いている間の「3 マス以内」は、箱のマスから測ります。
  `szMemo` は管理用のメモ（UTF-8・63 バイトまで。プレイヤーには出ません）。
  **箱番号（`wBoxNo`）は全マップ通しで重ならない 1〜1024 の番号**で、宝箱番号（`wChestNo`）とは別に数えます。足す時に省くと空き番号が自動で振られます（指定もできます。ほかの箱と重なる・範囲の外だと断ります）。箱の中身はこの番号ごとに持つので、**消した箱の番号は使い回しません**（マップごとに「使った最大番号」を覚えていて、自動で振る番号はそれより後ろ）。直す時は `get` で読んだ `wBoxNo` を付けたまま書き戻してください（省くと新しい番号が振られ、前の番号の箱の中身は誰も取り出せなくなります）。
- 見えるのは本人（プレイヤー）の画面だけです。NPC・敵・傭兵・宝箱の敵の動きはベースのパーツで決まります。管理者もふつうは印どおり（宝箱の記録も本人のもの）ですが、ゲーム内の管理者ウィンドウで「印で隠れたNPCも表示」をオンにしている間は、ベースのパーツのまま見えます。
- 橋の上下（立体交差）・見える範囲（`byViewRange`）の視界・マップ全体の灯りの計算はベースのパーツのままです。壁が通れる・床になるなどの見た目と通れるかを変える用途に使ってください。
- 例（港の倉庫の宝箱。開く前は閉じたパーツ、開いた後は 1235。薬草（item 12）が入っている。もう 1 つは依頼 B を終えた人にだけ橋がかかる）:
  `{"swaps":[{"kind":1,"x":12,"y":30,"wParts":1235,"wGiveItem":12,"szMsg":"宝箱を開けた！ 薬草を手に入れた。","szMemo":"ルシー 港の倉庫の奥"},{"kind":0,"x":20,"y":8,"wFlag":601,"byCmp":0,"wParts":1301}]}`
  橋のパーツは、ふだんの（印が無い）人の見た目＝マップのパーツ（`sbo_map_tiles`）を川のまま残しておき、`wParts` に橋のパーツを入れます。
- 読むだけの一覧：`/api/data/chests`（MCP は `sbo_chests`）が全マップの宝箱を宝箱番号の順に返します。`chests` は `{chestNo, mapNo, mapName, x, y, wParts, wGiveItem, item（アイテム名）, szMsg, szMemo}`、`retired` は使ったがもう無い（消した）番号、`nextNo` は次に自動で振る番号です。キャラの読み出し（`char` の `flags.chests`）に、そのキャラが開けた宝箱の番号が出ます（プレイヤーだけ。読むだけ）。
- リサイクル箱の読むだけの一覧は `/api/data/recycle`（下の「リサイクルボックス」）です。
- 管理ページ（`/admin` の「マップ確認」→編集モード→「印で変わるマス・宝箱・リサイクル箱」）でも、種類を選び、マスを選んで足す・直す・消すことができ、全マップの宝箱の一覧（クリックでそのマスへ）も見られます。マップ上の枠は、宝箱が緑・リサイクル箱が水色・印で変わるがオレンジです。

### 見える範囲（`map` の `byViewRange`）

洞窟や迷路のように、暗くはしないけれど、遠くや壁の向こうを見えなくしたいマップに使います。

- `byViewRange` は 0〜10 です（0 は制限なし）。1 以上にすると、自分から丸く `byViewRange` マス（画面の端の 7 マスまで）の中で、壁にさえぎられていない所だけが見えます。
- 見えないマスは黒くなり、そこにいるキャラや名前も見えません。一度見たマスは、離れても薄暗く残ります（地図が埋まっていく感じ）。同じマップに入り直すと消えます。
- 明るさ `byLightLevel` が 1 以上の場所では、これまでどおり灯りのほうが使われます。`darkAreas` の「暗くしない」所では効きません（地上は見通しよく、洞窟だけ見える範囲を狭く、ができます）。
- `wViewHideParts` に mapParts の番号を入れると、見えない所を黒ではなくそのパーツで描きます（森なら草原や木のパーツにすると、ダンジョンではなく見通しの悪い森のようになります）。見えている所との区別がつくよう、見えない所には白い霧がかかり、一度見た所は本当の地形を薄い霧ごしに描きます。
- ゲーム内の管理者ウィンドウ（マップ情報→「明るさ・灯り・見え方の設定...」）の「見える範囲」「見えない所」でも設定できます。

### ダメージ床（`mapParts` の `byDamage`・`byPoison`）

毒沼や溶岩のように、歩くとダメージを受ける床はパーツに設定します。そのパーツで塗ったマスは全部ダメージ床になるので、通路一帯でもイベントを並べる必要はありません。

- `byDamage` は、そのマスに1歩入るたびに減る HP（0〜255、0 ならダメージ床ではない）。床のダメージでは倒れず、HP は 1 で止まります。立ち止まっている間は減りません。
- `byPoison` は、踏むと毒になる秒数（0〜255、0 なら毒にならない）。毒は 2 秒ごとに `byDamage` ずつ減ります（これも HP は 1 で止まる）。もう毒の時はかけ直さないので、沼を歩き続けても毒の時間は延びません。
- 「ついていく」でついていっているプレイヤーも踏みます（傭兵は今は踏みません）。
- 当たり判定 `byHitType` とは別なので、足跡（砂）や水の波紋と一緒に使えます。
- ゲーム内の管理者ウィンドウ（マップ→マップパーツ）の「ダメージ床」「毒」の欄でも設定できます（「送信」で反映）。

### 敵を全部倒すと開く扉（`map` の `events` の扉 `byType` 1）

部屋の魔物を全部倒すと開く扉を作れます。

- 扉イベント（`events` の `type` 3）の詳細の `byType` を 1 にします（0 は今までどおりの「カギ不要」）。
- 数える範囲は `wAreaX1`・`wAreaY1`（左上）〜 `wAreaX2`・`wAreaY2`（右下）の四角で、右下の列・行も含みます。4 つとも 0 ならマップ全体を数えます。
- 数えるのは範囲の中で生きている戦闘1・戦闘2・宝箱の敵（正体を現す前も含む）です。傭兵・置いた魔法・NPC発生元そのものは数えません。
- 範囲に敵がいなくなると自動で開き（扉の音と「扉が開いた！」のメッセージ）、敵がいない間は開きっぱなしです。`byTimeClose` は使いません。
- 発生元から敵がまた出てくると閉まります。扉のマスに誰か立っている間は閉めずに待ちます。
- 閉まっている間は扉コマンドや S キーでは開かず、「まだ魔物の気配がする…（残り N 体）」と出ます。傭兵も開けられません。
- 討伐チャレンジの空間では、その空間の敵だけを数えて空間ごとに開け閉めします。
- ゲーム内の管理者ウィンドウ（マップ→イベント→扉）の「種別」で「敵を全部倒す」を選び、「範囲 左上X,Y」「範囲 右下X,Y」に座標を入れても設定できます。

### 低いパーツ（`mapParts` の `byLow`）

水面や柵のように、ぶつかって通れないが低い物は `byLow` を 1 にします（0 なら普通）。

- キャラは通れません（当たり判定 `byHitType` はそのまま）。その代わり、暗いマップの灯り・弓矢・飛ぶ特技・見通しの判定が、このパーツのマスを越えていきます（カウンターと同じ扱い）。
- 保存形式の大きさは変えていません。`SboDataMapPartsInfo.dat` では `byLight` の最上位ビット（0x80）に入れていて、今のデータ（灯りは 0〜7）はそのまま読めます。データAPIの `byLight` は 0〜7 のままで、`byLow` は別の項目です。
- ゲーム内の管理者ウィンドウ（マップ→マップパーツ）の「低い(灯り・矢が通る)」チェックでも設定できます（「送信」で反映）。

### 立体交差の橋（`mapParts` の `byHitType` 19・20）

当たり判定 19 は「橋（縦に渡る）」、20 は「橋（横に渡る）」です。どちらも通れます。

- 地面から 19 のマスに上下から乗った人は橋の上を、左右から入った人は橋の下をくぐって通ります（20 はその逆）。上の人と下の人はぶつからずにすれちがえます。下をくぐる人は、橋の絵の後ろに隠れて見えます。
- 上か下かは、橋のマスから地面に降りるまで覚えています（高速道路に乗ったかどうかのように）。橋のマスを何枚も並べると広い橋になり、上の人はとなりの橋のマスへ横にずれられます。
- 上の人は橋の横から地面へは降りられず（橋の向きの端から降りる）、下の人は橋の向きの端から地面へは出られません（横切って抜ける）。向きはどこでも変えられます。
- 普通のマップでも、19・20 のパーツを置けば使えます。今ある橋のパーツ（水の上の橋など）の当たり判定を変えると、その橋でもこの決まりになるので、交差に使う時は同じ絵でパーツを足して 19・20 にするのがおすすめです。
- ログアウトした時は、上か下かに合う向きで保存するので、再開しても同じ側にいます。

### NPC（`char`）

- NPC は **`npcId`（NPC番号）** で見分けます。`id`（キャラのテーブル番号）は再起動で詰め直されて変わることがありますが、`npcId` は変わりません。
  セーブデータの `dwNpcID` 列に保存され、前のセーブデータを読んだ時は自動で振ります。
- 書き換えられるのは保存される NPC だけです（プレイヤー・発生元から出た敵は断ります）。
- 足す時は `sbo_add` で `dwMapID`・`dwX`・`dwY` を必ず渡します（他は省くと 0 や空）。
- 消す時は `sbo_update` の変更に `{"deleted": true}` を入れます。
- 元に戻す・しおりで戻すと、足した NPC は消え、消した NPC は **同じ `npcId` で** 足し直します。
- 遊んでいる間に変わる項目（位置・向き・HP など）は、「後から変わったか」の判定では見ません（歩き回る NPC でも戻せる）。
- `byGhost`：1 にすると **半透明（霊）で描かれます**（見た目だけ。0=ふつう。保存される）。旅人の「隠れる」と同じ透け具合ですが、敵に見つかりにくくなる効果はありません。話せる NPC にも敵にも付けられます。NPC発生で出る敵は、`stTmp` の `byGhost`（無ければ発生元の `byGhost`）になります。

**アカウント名・パスワード・IP アドレス・MAC アドレスは、どのキーでも出しません。**

項目名はソースの変数名と同じです（`szName`・`wMana` など）。意味・範囲・他のデータの番号の参照は
`sbo_schema`（`/api/data/schema`）で見られます。

## 迷路（`subGame` の `byType` 2）

マップの四角い範囲を、誰もいなくなるたびに自動で作り直す迷路です。迷路ごとに見た目・通路の太さを変えられ、いくつでも置けます。
BGM・暗さはマップの設定（`map` の `byBGM`・`byLightLevel`）なので、雰囲気を変えたい迷路は別のマップに置きます（マップは管理者ウィンドウで作る）。

- 足す: `sbo_add` で `{"kind":"subGame","records":[{"byType":2,"detail":{...}}]}`。止める: `sbo_update` で `{"byType":0}`（入口・ゴールのイベントを外す。描いた迷路の形はマップに残る）。
  元に戻す・しおりで戻すと、足した迷路は止まります。`byType` 0 の枠は迷路にして使い回せます。
- `detail` の主な項目
  - `dwMapID`・`byX1`〜`byY2`: 迷路を作る範囲（マップの中。外周は壁になる）
  - `byStartX/Y`: 入口のマス（範囲の外）。ここに乗ると迷路の中のランダムな所へ飛ぶ。`wChipIDStart` がこのマスに置かれる
  - `byGoalToX/Y`: ゴールに着いた後に出るマス（範囲の外）。ゴールの位置は作るたびに変わる（`wChipIDGoal`）
  - `wChipIDRoad`・`wChipIDBlock`: 道と壁のパーツ（壁は通れないパーツにする）
  - `wChipIDRoad2`＋`byRoad2Rate`・`wChipIDBlock2`＋`byBlock2Rate`: 道・壁に混ぜるパーツと割合(%)（落ち葉・花・コケなど。0 で混ぜない）
  - `wChipIDBlockFace`: すぐ下が道の壁の下の段に置くパーツ（石壁の側面など。0 で使わない）
  - `byPathWidth`: 通路の太さ 1〜3 マス（0 は昔からの 2 マス）。範囲が同じでも 1 だと入り組み、3 だと広々する
  - `wChipIDBridgeV`・`wChipIDBridgeH`・`byCrossRate`: 立体交差。交差できる場所のうち `byCrossRate`%（0〜100）を橋にします。
    橋のパーツは当たり判定 19（縦に渡る）・20（横に渡る）のもの（片方だけでもよい）。橋の上の道と下の道は別の道で、橋の上では曲がれません。
    交差がある迷路も、どこからでもゴールへ行けるように作ります（範囲が 7×7 区画より狭いと交差は作りません）
- 設定を変えると、中に誰もいなければすぐ作り直します（遊んでいる人がいれば、みんな出て 5 秒後）。

## 作り手とレシピ（`maker`・`recipe`）

町の作り手に頼んで、材料から物を作ってもらう仕組みのデータです。**サーバーのデータなので公開リポジトリには入れません。**
`SBODATA/SboDataMakerInfo.dat`・`SboDataRecipeInfo.dat` が無い時は「作り手 0 件・レシピ 0 件」で起動し、
管理ページの「レシピ」タブか API で初めて保存した時に作られます。

- 作り手を足すと番号（0 から）が決まります。NPC（`char` の `szNpcSpeech`）の台詞を `@c00` のように **`@c` + 作り手の番号 2 桁** にすると、
  その NPC に話しかけた時（S キーでも）に作り手の画面が開きます。`@0`〜`@9`・`@a`・`@k` とはぶつかりません。
- `maker`：`byState`（1 有効・2 停止中・0 削除済み）・`szName`・`szMsgTalk`・`szMsgDone`・`szMsgLack`。台詞は `@1`（改行）・`@2`（文の終わり）などが使えます。
- `recipe`：`byState`・`byMaker`・`wSort`（小さい順に並ぶ）・`wItem`・`byCount`（1 以上）・`awMatItem`（4 つ。使わない欄は 0）・`abyMatCount`・`dwGold`（手数料）。材料は 1 種類以上必要です。
- 材料は持ち物（装備中・捨てられない物を除く）のあと預かり所から使われます。できた物は持ち物へ、いっぱいなら預かり所へ届き、両方いっぱいなら断られます。
- 消す時は `byState` を 0 にします（空き枠になり、次に足す時に使い回されます）。
- 変更はログイン中のプレイヤー全員にすぐ届きます。下見 → 反映・変更履歴・元に戻すは他の種類と同じです。

例（始まりの町の料理人）：

```json
{"kind": "maker", "records": [{"szName": "料理人", "szMsgTalk": "いらっしゃい。@1何を作りましょうか？", "szMsgDone": "はい、できました。@2", "szMsgLack": "材料が足りないようです。@2"}]}
{"kind": "recipe", "records": [{"byMaker": 0, "wSort": 10, "wItem": 215, "byCount": 1, "awMatItem": [228, 148, 0, 0], "abyMatCount": [2, 1, 0, 0], "dwGold": 10}]}
```

## ギルドの仕事依頼（`quest`）

ギルドの人に話して依頼を受け、受けた人（とそのパーティ）にだけ見えるNPC（ワープポータル・宝箱・人）をたどって進める仕組みのデータです。
**サーバーのデータなので公開リポジトリには入れません。** `SBODATA/SboDataQuestInfo.dat` が無い時は「依頼 0 件」で起動し、API（`add`）で初めて保存した時に作られます（管理ページの編集タブは次の段階）。
今は「ポータルで移る・宝箱で依頼の品をもらう・ギルドで渡して報酬をもらう」と、下の「討伐チャレンジ」までです（敵を倒した数を数える依頼は次の段階）。

ゲーム内の管理者ウィンドウ（その他→「ギルドの依頼」）でも、一覧を見る・直す・足すができます（消すことはできないので、出したくない時は状態を「止める」に）。書き込みはこの API と同じ確認を通り、だめな時は理由が出ます。見えるNPCの出る場所はゲーム画面の左クリック、ポータル・入口の行き先は右クリックで、いま居るマップの座標が入ります。

- ギルドの人は `char` の NPC です。台詞（`szNpcSpeech`）を `@g00` のように **`@g` + ギルド番号 2 桁** にすると、話した時に `byGuild` が同じ依頼の一覧が開きます（受ける・取り消す・渡すはここだけ）。
  **`@g` + ギルド番号の後ろに文を書くと、その文を先に出してから一覧を開きます**（思い出の本の `@r` と同じ作り）。例：`@g10【受付】@1いらっしゃい。@0`（`@0`＝入力待ち、`@1`＝改行。最後が `@0`・`@2` でなければ `@0` を足す）。`@g10` だけなら今まで通りすぐ一覧が開きます。地方ごとに窓口の台詞を変えられます。
  後ろの文が無い窓口でも、`byLevelMin`（下記）で依頼が隠れた人にだけ「今のレベルに合った依頼は、こんな感じです。」（1 件も出ない時は「いまのレベルに合う依頼はありません。」）と出ます。自前の台詞がある窓口ではそちらが先で、この一言は出ません。
- 依頼を足すと `wID`（依頼番号 1〜511）が自動で振られます。プレイヤーの「受けている依頼」「クリア済み」はこの番号で覚えるので、変えられません（`id` は配列の番号で別物）。
- 決まり：1 人 1 つまで。パーティの誰かが受けている依頼があると、仲間は同じ依頼しか受けられません（違う依頼の人は仲間になれません）。
  取り消しはギルドの人の近くでだけでき、ばつはありません（依頼の品・旗・段は消えます）。
- 進み具合は保存されます（`char` の読み出しの `quest`：`questId`・`step`・`flags`・`counts`）。見えるNPC は保存せず、約 1 秒ごとに作る・消すを合わせます。
  見えるNPC は当たり判定が無く、攻撃・ターゲット・ついていく・取引の相手にはできません。
- `goals`：段ごとの「いまの目的」の文（`byStepCount` 個まで。4 つまで）。コマンドの「目的」と一覧に出ます（物語の目的は思い出の本の `goals`）。
- `npcs`（8 つまで。配列で丸ごと置き換え）：`dwMapID`（マップの `dwID`）・`byX`・`byY`・`byDir`・`byKind`（1 ポータル・2 宝箱・3 人）・`wGrpID`（キャラ画像）・`szName`・`szSpeech`、
  出る条件（`byStepMin`〜`byStepMax`・`byFlgNeed`・`byFlgHide`）、話した時のはたらき（`dwDestMapID`・`byDestX`・`byDestY`＝ポータルの行き先、`wItem`＝宝箱で渡す物、`bySetFlg`＝立てる旗 1〜16、`byNextStep`＝進む段・255 は変えない）。
- 出口は見えるNPC ではなく、**今あるマップのイベント**（`map` の `events`）で作ります（データだけで足りる）。
- 最後の段で、`wQuestItem`（依頼の品）を持っているとギルドで渡せます。渡すと `dwGold`・`dwExp`・`wRewardItem` がもらえ、`byOnce` が 1 ならクリア済みになって一覧から消えます。
- 止める時は `byState` を 0 にします（一覧に出なくなる。受けている人は続けられる）。変更はすぐ反映されます。
- 受ける条件の印：`wNeedFlag`（この印が立っている人だけ受けられる）・`wNotFlag`（この印が立っている人は受けられない）。キャラの印の番号（0〜1023）で、**65535＝条件なし**（足す時に省くと条件なし。古い依頼も条件なし）。
  合わない人にはギルドの一覧にも出ず、受ける操作も断られます（すでに受けている人は続けられる）。討伐チャレンジをパーティで受ける時は、一緒に受ける仲間の誰かが合わないと全員受けられません。
- 最低レベル：`byLevelMin`（0〜99。**0＝制限なし**。足す時に省くと 0。古い依頼も 0）。キャラのレベルがこれ未満の人にはギルドの一覧に出ず、受ける操作も「この依頼を受けるには、レベル○が必要です。」と断られます。
  管理者は常に見えて受けられます。すでに受けている人の続き・取り消し・渡すは今まで通りです。討伐チャレンジをパーティで受ける時は、一緒に受ける仲間の誰かが足りないと全員受けられません。範囲外（100 以上）は拒否されます。
- 取り消しで戻すお話：`wCancelStory`（0〜255。**0＝何もしない**。足す時に省くと 0。古い依頼も 0）。思い出の本のお話（`story` の `wID`）を指定すると、プレイヤーが**ギルドで依頼を取り消した時**に、そのお話と `wPrevStory` でつながる後のお話の印・数値・クリア済みの印・`awTakeItem` の持ち物・`awTakeChest` の宝箱が、思い出の本のやり直しと同じように最初に戻ります（やり直しの回数は増えません）。途中まで進めた依頼を取り消してもう一度受けた時に、続きからにならないようにするためのものです（例：ミニシナリオ「レオカーン王の柩」）。戻した持ち物か宝箱があれば、取り消しの文の末尾に「（進めていた分は最初に戻りました）」が付きます。
  依頼の完了（渡す）・パーティ離脱などで自動的に取り消される時・管理者ウィンドウからの変更では戻しません。実在しないお話の番号は拒否されます（`story` の `wID` は 1〜255）。
- 導入のお話：`szIntro`（最大 1023 バイト。省くと空）。受けていない依頼で決定を押すと、まずこの文をメッセージ窓で 1 ページずつ読み、読み終わったら「受けますか？」を出します（途中でキャンセルすると何も起きず一覧に戻る）。NPC の台詞と同じ制御コード（`@0`＝入力待ち＝次のページ、`@1`＝改行、`@2`＝終わり）。空なら今まで通りすぐ確認。文はギルドの一覧には載せず、決定を押した時に別に送るので長くても通信は増えません。

アイテム番号・画像 ID・マップの ID は仮です。`item`・`map` を見て本物に置き換えてください。出口は既にあるイベント（18,106）→（9,91）をそのまま使います。


### 討伐チャレンジ（`byChallenge`）

装備・特技・レベルをそろえて、だれが受けても同じ状態で挑む依頼です（`byChallenge` 1＝**異空間**：挑戦している組にだけ見え、組ごとに別の空間なので何組でも同時に挑めます。2＝**闘技場**：ふつうの世界の人も戦う様子を観戦できます。挑戦者からも観客が見え、周りへの発言もおたがいに届きます。観客は見えるだけで、敵に攻撃したり邪魔したりはできません。闘技場は同じ依頼を一度に 1 組だけ）。

- `byChallenge`：1（異空間）か 2（闘技場）で討伐チャレンジ。`wLoanStTmp`：貸し出しセットにする `stTmp`（ステータステンプレート）の id。`byMemberMin`：必要な人数（0・1 は一人でも可、2 以上はパーティを組んでいないと受けられない）。
- 受けると、近く（同じマップの 8 マス以内）にいるパーティの仲間全員が一緒に受けます。後から入った仲間は参加できません。
- `npcs` の `byKind` 4 = **入口**。受けた人が乗る（か話す）と、近くで同じ依頼を受けた仲間と一緒に `dwDestMapID`・`byDestX`・`byDestY` へ移り、全員が貸し出しセットの状態になります。
  入口の `bySetFlg`・`byNextStep` は入った全員に効きます。異空間は何組でも同時に入れます。闘技場は一度に 1 組だけ（使用中は「別の組が闘技場で戦っています」）。傭兵を連れていると入れません。
- `byKind` 5 = **敵**。挑戦が始まった時に `byX`・`byY` に出ます。強さは `wStTmp` の `stTmp`（動き方は戦闘 1・戦闘 2 のどちらか。それ以外は戦闘 2 になる）。経験値・お金・落とす物は出しません。
  敵と挑戦している組は、その組だけの空間にいるので、ほかの人とはぶつからず攻撃も届きません。闘技場は観客から見えるので、観客席から見渡せる場所に**入口からしか入れない部屋**を作ると観戦しやすくなります（観客が中に入ると、見えている敵や挑戦者と重なって見えます）。
  あきらめて帰る出口を付ける時は、部屋の中にマップのワープ（座標変更・マップ間移動のイベント）を置きます。部屋に着いた後にワープで動くと、その人は中断して元の姿に戻り、ワープの行き先に残ります。
- 貸し出しセットは、レベル・力〜運・最大 HP/Mana（満タン）・特技 16 枠・持ち物・お金・属性。持ち物の武器・鎧・盾・兜・小手・靴・アクセサリは種類ごとに最初の 1 つを自動で装備します。職業と見た目はそのまま。
- 本物の状態はサーバーのメモリに控え、**保存ファイルには常に本物と入る前の場所を書きます**（サーバーが落ちても次は元のキャラで始まる）。
- 敵を全部倒すと「討伐成功！」とタイムを知らせ、3 秒後に全員元の状態で入る前の場所へ戻り、最後の段＋旗 16（成功の印）。ギルドで渡すと報酬。**報酬は初めての時だけ**で、2 回目からは報酬なし（何度でも挑めます。`byOnce` が 1 なら一度きり）。
- 倒れる・パーティを抜ける・依頼を取り消す（中ではできない）・町転送などで戦う場所のマップを出る・部屋の出口のワープを踏む・切断すると、その人だけ中断して元に戻ります（お金は減りません。依頼は受けたままなのでまた挑めます）。全員いなくなると敵は消えます。
- 挑戦中は預かり所・取り引き・作ってもらう（料理など）・ギルドでの受ける/取り消す/渡すはできません。旗 16 は成功の印に使うので、ほかの見えるNPC では使わないでください。

例（実験場の小部屋で 2 人以上。`stTmp` の id・座標は仮）：

```json
{"kind": "quest", "records": [{
  "byGuild": 1, "wSort": 20, "szName": "試練：森の番人", "szExplain": "決められた装備で、森の番人を倒してください。",
  "dwGold": 300, "dwExp": 100, "byStepCount": 2, "goals": ["光る入口から試練の間へ", "ギルドへ報告する"],
  "byChallenge": 1, "wLoanStTmp": 40, "byMemberMin": 2,
  "npcs": [
    {"dwMapID": 37, "byX": 12, "byY": 95, "byKind": 4, "wGrpID": 141, "szName": "試練の入口", "dwDestMapID": 37, "byDestX": 20, "byDestY": 100},
    {"dwMapID": 37, "byX": 25, "byY": 100, "byKind": 5, "wGrpID": 50, "szName": "森の番人", "wStTmp": 41}
  ]
}]}
```

## キャラのフラグと会話データ（`flag`・`talk`）

キャラごとにずっと残る「フラグ」と、フラグを見て町の人の台詞を出し分ける「会話データ」です。**サーバーのデータなので公開リポジトリには入れません**
（`SBODATA/SboDataFlagNameInfo.dat`・`SboDataTalkInfo.dat`。無い時は 0 件で起動し、API（`add`）で初めて保存した時に作られます）。
ゲーム内の管理者ウィンドウの画面は次の段階で、今は API（とゲーム内の管理者用の通信）で読み書きします。

### フラグ（キャラごと・保存される）

- **印**（ON/OFF）が 1024 個（番号 0〜1023）、**数値**（0〜255）が 128 個（番号 0〜127）。キャラのセーブデータに入り、サーバーだけが持ちます（他人・NPC・本人のクライアントにも送りません）。古いデータは全部 0（印は全部 OFF）で始まります。
- 番号の割り振りの目安（コードでは強制しません）：印は 1〜199 本筋・200〜599 地域・600〜899 お使い・900〜1023 予備。数値は 0〜127。
- キャラのフラグは **読み取りだけ**：`char` の読み出し（プレイヤーだけ）の `flags`（`bits`＝立っている印の番号の並び、`nums`＝0 でない数値 `{"番号": 値}`）。API からは書き込めません（ゲーム内の管理者用の通信 `CMD_ADMINCHARFLAG` で変えます）。
- 印や数値を動かすのは、会話データ（話した後）と、ギルドの依頼（完了した時）です。

### 名前表（`flag`）

番号に付ける名前の表です。1 件が「種類＋番号＋名前」で、**同じ種類・番号の組は 1 件まで**。

- `byState`：1＝有効・0＝削除済み（枠だけ残る。同じ種類・番号を使い直す時は、足さずにその枠の `byState` を 1 に戻して名前を付ける）。足す時に省くと 1。
- `byKind`：0＝印・1＝数値。`wNo`：番号（印は 0〜1023、数値は 0〜127）。`szName`：名前（UTF-8 で 95 バイトまで。全角 20 字ほど）。
- 最大 1152 件（印 1024＋数値 128）。

```json
{"kind": "flag", "records": [
  {"byKind": 0, "wNo": 1, "szName": "港町の事件を解決した"},
  {"byKind": 1, "wNo": 0, "szName": "港町の手伝いをした回数"}
]}
```

### フラグのグループ（メイン-サブ。`flagGroup`）

印・数値の番号の帯（1 グループ 16 本まで）に「メイン名」を付けて、**「メイン-サブ」で管理する**ための表です（例：ルシー＝印 100〜139。後から番号が飛んだ場所に「続きの帯」300〜319 を足せます）。**見せ方・入力・絞り込みだけの層**で、会話データ・依頼・NPC の `wShowFlag`／`wHideFlag`・思い出の本などが覚えている**番号は一切変わりません**（グループを足しても消しても、キャラのフラグも他のデータも動きません）。サーバーのデータで、`SBODATA/SboDataFlagGroupInfo.dat`（無ければ 0 件）に入ります。

- 項目：`wID`（グループ番号 1〜255。**足す時に自動で振られ、変わりません**。読むだけ。`id`＝配列の番号とは別）・`byState`（1＝有効・0＝削除済み。足す時に省くと 1）・`byKind`（0＝印・1＝数値。省くと 0）・`szName`（メイン名。UTF-8 で 63 バイトまで。有効な間は空にできません）・`bands`（番号の帯の配列 `[{"wFrom": 先頭, "wTo": 最後}, ...]`。**1〜16 本**で、**順番がサブの数え順**。配列で丸ごと置き換え。各帯は**両端を含み**、印は 0〜1023、数値は 0〜127、`wFrom` <= `wTo`。**足す時は `bands` か `wFrom`／`wTo` のどちらかを必ず指定**）・`wFrom`／`wTo`（**互換**。帯 1 のこと。`bands` を使わずこの 2 つだけを渡すと帯 1 本のグループとして足せ、直す時は帯 1 だけが変わって帯 2 以降は残ります。`bands` と一緒に渡す時は `bands[0]` と同じ値にします。取得した記録には `bands` と一緒に帯 1 の `wFrom`／`wTo` も出ます）・`wSort`（並び順。小さい順、同じなら番号順）。最大 255 件。
- **帯は重ねられません**：同じ種類（`byKind`）の、有効なすべてのグループの**すべての帯同士**（同じグループの中の帯同士も）が重なるのは不可です（端が 1 つ重なるのもだめ）。種類が違えば同じ番号の帯でもかまいません。削除済み（`byState` 0）の帯は数えないので、同じ帯を別のグループで使い直せます。削除済みの枠を有効に戻す時も重なりを確かめます。
- **メイン-サブの計算**：番号 n が、有効なグループのどれかの帯に入るなら、**メイン＝そのグループ・サブ＝帯の順に続けて数えた番号（1 始まり）**。帯 1 の中なら n − 帯 1 の `wFrom` + 1、帯 2 の中なら（帯 1 の番号の数）+ n − 帯 2 の `wFrom` + 1、のように続けます（例：ルシー＝帯 1 の 100〜139＋帯 2 の 300〜319 なら、100〜139 がサブ 1〜40・300〜319 がサブ 41〜60。「ルシー-41」は 300）。表示は「ルシー-3（103）」のように「メイン名-サブ」と元の番号を併記します。どのグループにも入らない番号は今まで通り番号だけです。
- `flag`（名前表）の記録にも、計算した **`group`（メイン名。入らなければ空）・`sub`（サブ。入らなければ 0）** が付きます。**読むだけ**で、書き込みはできません（取得した記録の `group`・`sub` を今と同じ値で書き戻すのは許しますが、違う値は断ります）。
- 変更履歴・元に戻す・しおり戻しに乗ります（追加したグループを戻すと `byState` 0＝削除済みになります）。
- 管理者ウィンドウ（その他→フラグのグループ）で一覧・追加・更新・削除ができます（書き込みはこの API と同じ確認を通ります）。キャラのフラグの画面は一覧に「グループ」列（メイン-サブ）を出し、グループで絞り込めます。印・数値の番号を入れる欄（キャラのフラグ・会話データ・依頼・NPC の見える条件・思い出の本）は、数字のほかに **「グループ番号-サブ」（例 `3-2`。メイン名でも可）** も受け付け、番号の横に「ルシー-3」のようにメイン-サブを出します。思い出の本の編集には「グループから範囲を入れる」ボタンがあり、選んだ印のグループの帯を、帯ごとに消す印の範囲の欄へ（帯 1 を範囲 1、帯 2 を範囲 2 の順に）入れます。範囲の欄は 2 つなので、帯が 3 本以上のグループは入るだけ入れて、入れなかった帯を画面で知らせます。フラグのグループの画面の「番号の帯」は 1 つの欄にカンマ区切りで入れます（例 `100-139, 300-319, 500-509`。16 本まで。区切りは「,」「、」・範囲は「-」「〜」「~」・空白は無視・数字 1 つだけ（`120`）なら 120〜120 の 1 本・全角数字も可。読めない・17 本以上・範囲外・重なりは理由を出して断ります）。一覧には「100〜139, 300〜319」のように出ます。

例（ルシー＝印 100〜139＋300〜319。印 103 は「ルシー-4」、印 300 は「ルシー-41」）：

```json
{"kind": "flagGroup", "records": [
  {"byKind": 0, "szName": "ルシー", "bands": [{"wFrom": 100, "wTo": 139}, {"wFrom": 300, "wTo": 319}], "wSort": 10}
]}
```

帯 1 本だけなら、従来の書き方 `{"byKind": 0, "szName": "リノ", "wFrom": 140, "wTo": 149}` もそのまま使えます。後から続きの帯を足す時は、今の帯に新しい帯を加えた `bands` を渡します（`{"bands": [{"wFrom": 140, "wTo": 149}, {"wFrom": 400, "wTo": 409}]}`。帯の順に続けて数えるので、先頭の帯の並びは変えないでください）。保存ファイル `SboDataFlagGroupInfo.dat` は帯 1 が `wFrom`／`wTo`・帯 2〜16 が `awFromX`／`awToX`（`byBandCount` 列で本数）で、帯が 1 本だけの古いファイルもそのまま読めます。

### 会話データ（`talk`）

NPC（`char`）の台詞（`szNpcSpeech`）を **`@t` + 番号**（例 `@t012`＝会話セット 12 番）にすると、その人に話しかけた時にこのセットの台詞を出します。
台詞は話しかけた本人にだけ出ます（クライアントへは選ばれた 1 行だけを送り、会話データそのものは送りません）。台詞の書き方は NPC の台詞と同じ（`@0` 入力待ち・`@1` 改行・`@2` 点滅無しで入力待ち。普通の町の人と同じ会話の窓で、ページ送りもあります）。

- セットの項目：`wID`（会話セット番号 1〜999。**足す時に必ず指定**。ほかのセットと重ならず、あとから変えられない。`id`＝配列の番号とは別）・`szName`（管理用のメモ。63 バイトまで）・`byState`（1＝有効・0＝削除済み。足す時に省くと 1）・`lines`（最大 16 行。配列で丸ごと置き換え）。
- 行（`lines` の 1 要素）：
  - `byRank`：順位（小さいほど先に見る）。
  - 条件（全部に合った行だけ候補になる）：`awNeed`（立っている必要のある印。最大 4）・`awNot`（立っていてはいけない印。最大 4）・`abyCondNo`／`abyCondCmp`／`abyCondVal`（数値の条件。最大 2。比べ方 0＝以上・1＝ちょうど・2＝以下）・`byLvMin`／`byLvMax`（レベル下限・上限。0＝気にしない）。
  - 受けている依頼の条件：`wQuestID`（`quest` の依頼番号 `wID`。0＝条件なし）・`byQuestStepMin`／`byQuestStepMax`（段の範囲。0 から数え、`quest` の見えるNPC の `byStepMin`／`byStepMax` と同じ。`byQuestStepMax` の **255＝どの段でも**。省くと 255）。
    `wQuestID` が 0 以外なら、話した人が**いまその依頼を受けていて**、今の段が Min〜Max の間の時だけ合います。
  - 持っている物の条件：`wNeedItem`（`item` の番号。0＝条件なし）。0 以外なら、話した人がそのアイテムを**手持ちか大事な物の欄に 1 つ以上持っている**時だけ合います（預かり所は見ません。持っていても減りません）。
  - 取り上げる物：`wTakeItem`（`item` の番号。0＝取り上げない）。この行で話した後に、**手持ち → 大事な物の欄**の順にその品を 1 つ取り上げます（装備中の品は取りません。装備していない同じ品があればそれを取ります。預かり所は見ません）。引換券 → 景品のような引き換えに使い、`wGiveItem` と組みます。順番は「取り上げる品を持っているか → 渡す品を受け取れるか → 両方よければ取り上げて渡し、印・数値を動かす」。取り上げる品を持っていない時、渡す品を受け取れない時は、何も取らず印・数値・渡すも動かしません（台詞は言います）。取り上げると「○○を渡しました。」と知らせます。
  - `szSpeech`：台詞（1023 バイトまで。空だと「……」）。
  - 話した後：`awSetOn`（立てる印。最大 2）・`awSetOff`（消す印。最大 2）・`abyActNo`／`abyActOp`／`abyActVal`（数値の動き。最大 2。`abyActOp` 0＝「○にする」・1＝「○足す」（255 で止まる））。立てる→消す→数値の順に反映します。
  - 渡す物：`wGiveItem`（`item` の番号。0＝渡さない）。その行が選ばれて話した時、台詞のあとにアイテムを 1 つ渡し、「○○を手に入れました。」と知らせます（依頼の宝箱・報酬と同じ渡し方。持ち物がいっぱいなら預かり所へ。大事な物の印のある品は大事な物の欄へ入ります）。
    **毎回渡すかどうかはサーバーでは数えません**（話すたびに 1 つ渡します）。一度きりにしたい時は、同じ行の `awSetOn` に「もらった印」を入れ、`awNot` にも同じ印を入れてください（もらった後はその行が候補から外れます）。
  - はい・いいえで聞く：`byAsk`（0＝今まで通り・1＝聞く）・`szNoMsg`（いいえの返事。127 バイトまで。**空なら既定の「そうですか。また声をかけてくださいね。」**。行の話し手がだれでも自然に聞こえる一言にしてあります）。
    `byAsk` が 1 の行が選ばれると、サーバーは台詞を送りますが、**印・数値・渡す物・取り上げる物はまだ動かしません**（その人の「保留中の問い」として、会話セット番号・行・NPC・時刻を覚えるだけ）。クライアントは台詞を出し終えたあと、買い物などと同じ「はい／いいえ」の窓を出します（キーボードは決定・キャンセル、スマホは仮想パッドのボタン。キャンセルは「いいえ」）。
    - **はい**：保留が有効なら、今までと同じ反映をします（取り上げる→渡す→成功した時だけ印・数値。印が動けば見え直し）。有効とは、同じ NPC が 2 マス以内にいて（同じマップ・空間。見えている）、60 秒以内で、その行がまだ条件に合い、`byAsk` がまだ 1 の時です。1 つでも外れたら**黙って何も起きません**。
    - **いいえ**：何も動かさず、`szNoMsg`（空なら既定）を返します。
    - どちらの答えでも保留は消えます。別の NPC（や同じ NPC）にもう一度話した時・ログアウトでも消えます。マップ移動・空間移動・時間切れ・NPC から離れた後に届いた答えは捨てます。保留はサーバーのメモリだけで、保存しません。
    - 台詞の最後に、サーバーが制御コード `@y`（クライアントが「はい・いいえ」を出す合図）を付けて送ります。台詞が 1023 バイトぎりぎりでも `@y` が切れないよう、聞く行の台詞は 1021 バイトまでで切ります。台詞の末尾が `@0`・`@2` の入力待ちなら、それを読み終えてから窓が出ます。
    - 答えは新しい通信 `CMD_TALKANSWER`（クライアント→サーバー。`CMDPARA_DATA1` の `byData`＝1 がはい・0 がいいえ、`dwTblID`＝話しかけた NPC）で送ります。一般のプレイヤーが送れる通信で、返事（いいえの台詞）は `CMD_TALKMSG` で本人にだけ返ります。
- **「無し」の表し方**：印の番号は `65535`、数値の番号は `255`（印 0 を使えるよう 0 は「無し」ではありません）。配列を短く書くと、残りは「無し」になります。行の他の項目を省くと 0 です。
- 選び方：行を上から見て、条件に全部合う行を集め、**その中で `byRank` が一番小さい行たち**から選びます。同じ順位が複数あれば乱数のくじで 1 行。合う行が無い（セットが無い・削除済みも）時は「……」とだけ言います。
- 1 行ごとの台詞の長さは 1023 バイトまで、いいえの返事は 127 バイトまで（1 セット 16 行が通信の 1 パケット（64KB 未満）に収まる大きさ。いいえの返事を短くしてあるのはそのため）。

例（初めての人には事情を話し、印 1 が立っていれば礼を言って、手伝った回数（数値 0）を増やす）：

```json
{"kind": "talk", "records": [{
  "wID": 12, "szName": "港の漁師（事件の前後）",
  "lines": [
    {"byRank": 10, "awNot": [1], "szSpeech": "最近、港が荒れていてね…@0助けてくれないか。", "awSetOn": [2]},
    {"byRank": 5, "awNeed": [1], "szSpeech": "事件を解決してくれたんだってな！@0ありがとう。", "abyActNo": [0], "abyActOp": [1], "abyActVal": [1]}
  ]
}]}
```

### ギルドの依頼で動かす

`quest` に、受ける条件の印（`wNeedFlag`／`wNotFlag`。上の「ギルドの依頼」を参照）と、依頼を完了して報酬を受け取った時に動かす欄があります（古い依頼は「無し」として読めます）。討伐チャレンジの 2 回目からは（報酬と同じく）動かしません。

- `awDoneSetFlag`：立てる印（最大 2。65535＝無し。省いた時も無し）。
- `byDoneNumNo`／`byDoneNumOp`／`byDoneNumVal`：動かす数値（1 つ。番号 255＝無し。`byDoneNumOp` 0＝「○にする」・1＝「○足す」）。

### 印で見える・消えるNPC

`char` の NPC に、キャラの印で見える・見えないを決める欄があります（保存されます。町の人＝`byNpcType` 1（移動しない）・2（ランダム移動）向け。敵に付けても壊れませんが、見えない人は狙いません）。

- `wShowFlag`：この印が立っている人**にだけ**見える。`wHideFlag`：この印が立っている人には**見えない**。印の番号（0〜1023）で、**65535＝条件なし**（足す時に省くと条件なし。古い NPC も条件なし。0〜1023 と 65535 以外はエラー）。両方ある時は、両方の条件を満たす人にだけ見えます。管理者（管理権限のあるキャラ）も、ふだんは一般のプレイヤーと同じく印どおりに見える・見えない（ぶつかる・話せるも同じ）です。管理者ウィンドウ（その他→各種通知）の「印で隠れたNPCも表示」をオンにした管理者にだけ、印に関わらず全部見えます（キャラごとのメモリだけの設定で、既定はオフ。保存せず、ログインし直すとオフ。切り替えると、いるマップの条件付き NPC が出し直されます）。
- 見えない人にとっては、その NPC は居ないのと同じです（歩くのをふさがない・話せない・調べられない・押せない・ついていけない・攻撃や特技の対象にならない）。
- 印が動いた時（会話データ・依頼の完了・管理者ウィンドウでの切り替え）は、その人がいるマップの条件付き NPC が、その人にだけ出たり消えたりします。この API で条件を変えた時は、そのマップの全員に見え直しを送ります。
- 例（依頼で助けたピピが、助けた後＝印 5 が立った人にだけ町にいる。見張りの兵は印 5 が立った人には消える）：ピピの NPC に `sbo_update` で `{"wShowFlag": 5}`、見張りの兵の NPC に `{"wHideFlag": 5}`。印 5 は、依頼の完了（`awDoneSetFlag`）や会話データの `awSetOn` で立てます。

### ゲーム内の管理者用の通信（画面は次の段階）

管理者権限のあるキャラだけが送れます（依頼の編集 `CMD_ADMINQUEST` と同じ形で、書き込みはこの API と同じ確認を通ります）。`CMD_ADMINFLAGNAME`（名前表の一覧・書き込み）・`CMD_ADMINTALK`（会話データの一覧・書き込み）・`CMD_ADMINCHARFLAG`（キャラの印・数値の取得・変更。ログアウト中のプレイヤーも可）。

### ゲーム内の管理者ウィンドウの会話データ画面

- 「その他→会話データ」の一覧は、全マップの会話セットが 1 つに並びます。右端の「使用先」に、そのセットを使っている NPC を「マップ名：NPC名」で出します（複数なら「、」で並ぶ。どの NPC も使っていなければ「未使用」）。
- 一覧の上の「マップ」で、そのマップの NPC が使っているセットだけに絞り込めます（「すべて」で全部）。絞り込みの欄は、名前・番号・使用先（マップ名・NPC名）のどれかに部分一致すれば出します。
- キャラ情報の画面（「フラグ」ボタンの右）の「会話編集」は、選んだ NPC の台詞が `@t` + 番号のとき、その番号の会話セットの編集画面を直接開きます（セットがまだ無い番号なら、その番号で追加の画面になります）。
- 使用先はサーバーが知らせます。`CMD_ADMINTALK` の `LISTREQ` への返事は、マップの名前（`ADMINTALK_MAP`）→ 使用先（`ADMINTALK_USE`。保存されている NPC のうち台詞が `@t` + 数字のものを 1 体ごとに）→ 会話セット（`ADMINTALK_ITEM`）の順です（`MAP`・`USE` は小さい別の形 `CMDPARA_ADMINTALKUSE`）。

## 思い出の本（`story`）

クリア済みのミニシナリオを、キャラごとに最初からやり直せる仕組みです。NPC（語り部）の台詞を `@r` にすると、話した人に「思い出の本」の窓が開きます（`@g` のギルドの窓と同じ作りです）。

- 本に出るのは、**状態が出す（`byState` 1）で、話した人が `wClearFlag` の印を持っているシナリオ**だけ。`wSort` の小さい順（同じなら番号順）。何も無ければ「まだ思い出はありません」。
- シナリオを選ぶと確認が出て、「はい」で**そのシナリオと、`wPrevStory` でつながる後のシナリオすべて**を最初に戻します。後のシナリオがある時は確認に「『△△』もいっしょに最初に戻ります」と出ます。
  - `awFlagFrom`〜`awFlagTo`（最大 2 範囲。両端の印も含む。65535＝無し）の印を消す。
  - `abyNum`（最大 4。255＝無し）の数値を 0 にする。
  - `awQuest`（最大 4。0＝無し）の依頼のクリア済みの印を消す（一度きりの依頼もまた受けられる）。
  - `awTakeItem`（最大 8。item 番号。0＝無し）の持ち物を取り上げる。**大事な物の欄**にある分と、**手持ちの装備していない分**を全部消す（王家の鍵など、やり直しで持ち越したくない物に使う）。装備中の品と預かり所は触らない。持っていなければ何も起きない。取り上げた時は結果に「（○個の大事な物を手放しました）」と出て、持ち物がクライアントへ送り直される。
  - `awTakeChest`（最大 8。宝箱番号 0〜2047。65535＝無し。宝箱 0 も指せる）の宝箱の「開けた記録」を消す。本人の画面の宝箱は閉じた絵に戻り、もう一度開けて中身をもらえる（`awTakeItem` で鍵を取り上げるお話と組み合わせても詰まない）。**指定しない宝箱は戻りません**（宝は一度きり）。短い配列は残りが「無し」になり、足す時に省くと全部「無し」。開けていなかった宝箱は何も起きず、戻した時は結果に「（宝箱を○個戻しました）」と出ます。
  - 選んだシナリオの `byCountNum`（255＝数えない）の数値を +1（255 で止まる。「2 周目」の台詞の出し分けに使える）。
- その人が、戻す依頼（子孫を含む）のどれかを**いま受けている間はやり直せません**。語り部の近く（2 マス以内）でだけできます。
- `wID`（1〜255）は足す時に自動で振られ、変わりません（`wPrevStory` がこの番号で指す）。`wPrevStory` は存在するシナリオだけで、自分や後のお話は指せません（ループ不可）。

**報酬は初回だけ**：一度きりの依頼（`byOnce` 1）と討伐チャレンジは、報酬（お金・経験値・アイテム）を渡した時に「もらい済みの印」（キャラの `quest.questRewarded`）が付き、やり直してクリア済みの印が消えても残ります。2 回目からは報酬なしで、依頼の完了時の印・数値（`awDoneSetFlag` など）は今まで通り動きます（討伐チャレンジの 2 回目は動かさない）。依頼を終える時の表示には「（初回のみ）」が付きます。`byOnce` 0 の依頼は毎回報酬です。古い保存データは、クリア済みの依頼を「もらい済み」とみなして読みます。

例（ルシーの話 L2 を、印 110 を立てる依頼 3 のお話にする。前は L1。やり直す時に item 12 を取り上げ、宝箱 100 を開け直せるように戻す）：

```json
{"kind": "story", "records": [{"szName": "ルシー L2", "szExplain": "ルシーと港で再会する話", "byState": 1, "wSort": 20,
  "wClearFlag": 110, "wPrevStory": 1, "awFlagFrom": [110], "awFlagTo": [110], "awQuest": [3], "awTakeItem": [12], "awTakeChest": [100], "byCountNum": 5}]}
```

- クリアした印（ここでは 110）は、やり直しで消えるよう**範囲に含めます**。語り部やお話の中で**もらった印（もらい物の記録など）は、範囲の外に置きます**（範囲に入れると、やり直しで消えて二重にもらえてしまいます）。
- 印の番号は 0 から使えます。`awFlagFrom`・`awFlagTo` を短くすると、残りは「無し」になります（0 にはなりません）。

**いまの目的（`goals`）**：進めている途中のプレイヤーが、NPC の説明を聞きそびれても「次に何をすればいいか」をコマンドの「目的」の窓から見られるようにします（ギルドの依頼を受けている時の「いまの目的」と同じ窓に、続けて「シナリオ名＋目的文」で並びます）。

- `goals`（最大 8 行。配列で丸ごと置き換え）：各要素は `{awNeed, awNot, abyCondNo, abyCondCmp, abyCondVal, szGoal}`。条件は会話データの行と同じ形・同じ判定です（`awNeed` 最大 4＝立っている必要のある印、`awNot` 最大 4＝立っていてはいけない印、`abyCondNo`/`abyCondCmp`/`abyCondVal` 最大 2＝数値の条件。比べ方は 0 以上・1 ちょうど・2 以下。印の「無し」は 65535、数値の「無し」は 255）。省いた条件は「無し」、短い配列は残りが「無し」になります。`szGoal` は最大 127 バイト。
- 出し方：`byState` 1 のシナリオについて（`wClearFlag` の印は見ません。クリアした後も次の行き先を出したい時があるためで、クリアで消したい時は行の `awNot` にクリアの印を入れます）、`goals` を上から見て、`szGoal` が空でなく条件に全部合う**最初の行**の文を出します。合う行が無ければそのシナリオは出しません。複数のシナリオが同時に出ることもあります（`wSort` 順。自分の分だけで、仲間の分は出ません）。
- `goals` を省いて書くと今のままです（足す時に省くと目的なし）。読み出しでは、使っている最後の行まで返します。管理者ウィンドウの編集画面にはまだ欄が無く、そこから保存しても `goals` は消えません。
- キャラの印・数値が動いた時（会話データで話した後・依頼の完了・管理者ウィンドウのフラグ変更・思い出の本のやり直し）に、送り直されます。

例（印 100 が立つまでは「港のルシーに話しかける」、立ったら「灯台へ向かう」。`sbo_update` で）：

```json
{"goals": [
  {"awNot": [100], "szGoal": "港のルシーに話しかける"},
  {"awNeed": [100], "szGoal": "灯台へ向かう"}]}
```
- ゲームの中では、管理者ウィンドウの「その他→思い出の本」で一覧・編集・追加ができます（消せません。出したくない時は状態を「止める」に）。書き込みはこの API と同じ確認を通ります。

## 取引所（読むだけ）

受付に品を預けてゴールドで売る「取引所」（委託販売。仕様は `docs/market.md`）の今の状況を見る、読むだけの一覧です。AI からは書き換えられません。

- `/api/data/market`（MCP は `sbo_market`。管理ページ用は `/api/admin/data/market`）が `{items, accounts, total, limits}` を返します。
  - `items` … 出品（**新しい順**）。`{id（出品ID）, acc（出品者のアカウント）, seller（出品したキャラ名）, charId, itemId, item, price, fee（売れた時の手数料）, net（手取り）, time, date（出品した日時・日本時間）, limit, limitDate（期限）, state, leftSec}`。`state` は `on`（出品中）か `expired`（期限切れ。引き取り待ち）。売れた出品はその場で消えるので出ません。
  - `accounts` … アカウントごとの `{acc, on（出品中の数）, expired（期限切れの数）, gold（受付に貯まっていて受け取っていない売上）}`。
  - `total` … `{on, expired, onPrice（出品中の値段の合計）, gold（売上の合計）}`。`limits` … 決まり（`maxPut` 5・`days` 7・`feePercent` 5・`priceMax`・`range` 3・`listMax` 100）。
- 管理ページ（`/admin`）の「取引所」タブでも、アカウントごとの出品数・売上と、出品の一覧（アカウント・キャラ名・品で絞り込める）を見られます。

## リサイクルボックス（読むだけ）

マップに置いた「リサイクルボックス」（お金を取らないおすそわけの共有の箱。`map` の `swaps` の `kind` 2。置き方は上の「印で変わるマス・宝箱・リサイクル箱」）を、正面で調べる（Sキー）と開きます。仕様は `docs/recycle.md`。
中身と記録は**データの種類（`kind`）ではなく、読むだけの専用の一覧**で見ます。AI からは書き換えられません。

- `/api/data/recycle`（MCP は `sbo_recycle`。管理ページ用は `/api/admin/data/recycle`）が `{boxes, log, daily, limits}` を返します。
  - `boxes` … 箱番号 `boxNo` の順に、箱ごとの `{boxNo, mapNo, mapName, x, y, wParts（開いた絵）, memo（管理用のメモ）, kinds（種類の数）, total（個数の合計）, missing, stock}`。`stock` は入れた順の `{itemId, item（アイテム名）, count}`。中身は**箱番号ごと**に持つので、`missing: true` は「中身が残っているのに、その番号の箱がどのマップにも無い（消した）」という意味です（`mapNo` は -1）。
  - `retired` … 番号は使ったが今はどのマップにも無い（消した）箱の番号（使い回しません）。`nextNo` … 次に自動で振る番号（-1=使い切り）。`max` … 番号の上限（1024）。
  - `log` … 入れた・もらった記録（**新しい順**。最大 1000 件）。`{time（UNIX 秒）, date（日本時間の「年-月-日 時:分」）, acc（アカウント）, name（キャラ名）, boxNo（箱番号）, action（`put`=入れた・`take`=もらった）, itemId, item, count}`。
  - `daily` … 今日（日本時間）に 1 個以上もらったアカウントの `{acc, count, left（今日あと何個もらえるか）}`。
  - `limits` … 決まり（`maxKind` 20・`maxCount` 255・`dayLimit` 3・`logMax` 1000・`range` 3・`maxBox` 1024）。
- 管理ページ（`/admin`）の「リサイクル」タブでも、箱（箱番号・マップ・メモ）ごとの中身・今日もらった人・記録（アカウント・キャラ名・品で絞り込める）を見られます。

## つなぎ方（Claude Code）

1. 管理ページ（`/admin`）の「AI連携」タブで、キーを発行します。
   - **読むだけ** … 一覧・検索・履歴を見るだけ
   - **書き込みもできる** … 変更・追加・元に戻すもできる
   - 期限は 7 日・30 日・90 日・なし から選べます。キーは発行した時に一度だけ表示されます。
2. 表示されたコマンドを Mac のターミナルで実行します。

   ```sh
   claude mcp add --transport http sbo2003 https://sbo2003.urara-works.jp/mcp --header "Authorization: Bearer sboai_..."
   ```

3. Claude Code で「アイテムの剣を値段順に並べて」「戦士の Lv10 の必要経験値を 1.2 倍に」のように頼みます。

使わなくなったキーは「AI連携」タブで取り消してください。サーバーの環境変数 `SBO_AI_API=off` で、この API と `/mcp` を丸ごと止められます。

## 安全のしくみ

- **AI 用キー** … 管理者パスワードは AI に渡しません。サーバーにはキーの SHA-256 だけを保存します（`SBODATA/SboWebAiKeys.json`）。
- **下見 → 確定の 2 段階** … 書き込み（変更・追加・元に戻す）は、まず何も変えずに「変更前 → 変更後」の差分と `previewId` を返します。
  同じ内容に `previewId` を付けてもう一度呼んだ時だけ反映します（10 分以内・1 回だけ）。下見の後に誰かがそのデータを変えていたら反映しません。
  範囲外の数・長すぎる文字列・知らない項目名は、下見の時点で断ります。
- **すぐ反映・すぐ保存** … 反映すると、管理者ウィンドウから変えた時と同じようにログイン中の全員へ送り、データファイルもすぐ保存します。
- **変更履歴と元に戻す** … 反映するたびに変更前と変更後を `SBODATA/SboWebDataHistory.json` に残します（直近 500 件）。
  1 回の呼び出し（1 種類のデータ・何件でも）が履歴 1 件で、元に戻すのもその単位です。
  その後に別の変更があったデータは、`force` を付けない限り戻しません。追加した NPC は消し、作り手・レシピは削除（`byState` 0）にして戻します。
  それ以外の種類（マップパーツ・エフェクト）の追加は消せないので戻せません。
  管理ページの「AI連携」タブからも履歴を見て「元に戻す」ができます。
- **しおり（お試しの区切り）** … お試しで作り変える前に、名前を付けて「しおり」を付けておくと、
  その後の変更を「このしおりまで戻す」で種類をまたいでまとめて元に戻せます（下見 → 確定）。
  記録ごとに「しおりの時の姿」に戻すので、途中で何回変えていても 1 回で戻ります。NPC の追加・削除・マス目の書き換えもまとめて戻ります。
  AI 以外（管理者ウィンドウなど）からも変わったデータがあると、`force` を付けない限り戻しません。
  しおりは 100 個まで覚えます。しおりの後の履歴が 500 件より前に流れて消えていると戻せません。
  管理ページの「AI連携」タブの「しおり」から付ける・戻すができます。
  AI に頼む時の例:「しおりを付けてから、レジェンタの料理人の台詞をお試しで変えて」→ 見てやめるなら「さっきのしおりまで戻して」。
  「しおりを付けてから、この町に村人を 3 人足して、お店の品ぞろえを変えて、広場のマス目を石畳にして」→「しおりまで戻して」でも全部戻ります。
- **管理者ウィンドウの「元に戻す」にも出る** … AI の変更は、管理者ウィンドウの画面ごとの「元に戻す」にも「AIキー「名前」さんが変えた」として並びます。
  どちらから戻しても、もう一方の履歴はその後の変更として扱うので、知らずに上書きすることはありません。
- **日ごとの控え** … その日初めてそのデータを変える前に、データファイルを `SBODATA/AiBackup/日付/` に写しておきます（マップは全マップのファイル）。
- **呼び出しの回数** … キーごとに 1 分 300 回までです。

## HTTP の API

すべて POST・JSON です。キーは `Authorization: Bearer <キー>`（または `X-Sbo-Key: <キー>`）ヘッダーで渡します。

| URL | 渡すもの | 返るもの |
| --- | --- | --- |
| `/api/data/schema` | `{}` | 種類と項目の説明 |
| `/api/data/list` | `{kind, q?, match?, offset?, limit?, fields?}` | 一覧（`q` は名前の一部、`match` は `{"isPlayer": true}` のような値の一致） |
| `/api/data/get` | `{kind, id}` | 1 件 |
| `/api/data/tiles` | `{id, x?, y?, w?, h?}` | マップのマス目（`id` は `map` の番号） |
| `/api/data/chests` | `{}` | 全マップの宝箱の一覧（読むだけ） |
| `/api/data/dungeon/records` | `{id?, versionNo?, theme?}` | 日替わりダンジョンの版と最短記録（読むだけ。版ごとに上位 20 件。`seed`・`genVer`・`themeRef`（`theme: true` で写しの中身）が同じなら同じ形。仕様は `docs/dungeon-gen.md` の「番外編 段階2」） |
| `/api/data/dungeon/rebuild` | `{id}` | 日替わりダンジョン（`subGame` の `detail.byRebuildMode` が 1）を今すぐ作り直す（書き込みキーだけ。中の組は外へ戻り、新しいランダムなシードの版になる） |
| `/api/data/market` | `{}` | 取引所の出品（出品中・期限切れ）とアカウントごとの出品数・売上（読むだけ。下の「取引所」） |
| `/api/data/recycle` | `{}` | リサイクルボックスの箱ごとの中身と、入れた・もらった記録（読むだけ。上の「リサイクルボックス」） |
| `/api/data/tiles/set` | `{id, x, y, parts:[[...]], note?, previewId?}` | マス目を書き換える（下見 / 反映の結果） |
| `/api/data/map/resize` | `{id, top?, bottom?, left?, right?, fill?, check?}` | マップを広げる（縮められない。上・左に広げると座標を持つもの全部をずらす。`check:true` で確かめるだけ。履歴に残らず元に戻せない） |
| `/api/data/map/add` | `{cx, cy, fill?, szName?}` | マップを足す（番号はいちばん後ろ。履歴に残らず消せない） |
| `/api/data/update` | `{kind, updates:[{id, changes}], note?, previewId?}` | 下見 / 反映の結果 |
| `/api/data/add` | `{kind, records:[{...}], note?, previewId?}` | 下見 / 反映の結果 |
| `/api/data/history` | `{kind?, limit?}` | 変更履歴（新しい順。マス目は `kind: "tiles"`） |
| `/api/data/undo` | `{historyId, force?, note?, previewId?}` | 下見 / 反映の結果 |
| `/api/data/bookmark` | `{name, note?}` | しおりを付ける（書き込みもできるキーだけ。データは変わらない） |
| `/api/data/bookmarks` | `{limit?}` | しおりの一覧（新しい順。`changes` はしおりの後の変更の数） |
| `/api/data/rollback` | `{bookmarkId, force?, note?, previewId?}` | しおりまで戻す（下見 / 反映の結果） |

`job` の `levelUp` は、配列で渡すと丸ごと置き換え（件数も変わる）、`{"4": {"dwExp": 100}}` のようなオブジェクトで渡すとその行だけ変わります。
`item` の `byType` を変えると `detail` は 0 から作り直します（種別ごとの項目はスキーマの `detailByType`）。

## マップづくりの手伝い（パーツ図鑑・配置案）

マップパーツ（マス目に入る番号）には名前も意味も無いので、AI が新しい街やダンジョンを考えられるように、
**パーツ図鑑** と **配置案** を用意しています（`server/node/sbosvr_mapdesign.js`・管理ページの「パーツ図鑑」「配置案」タブ）。
どちらもゲームのデータは変えません。

- **パーツ図鑑**（`SBODATA/SboWebPartsDex.json`）… パーツごとの名前・タグ・使い方のメモと、組み合わせの見本（壁で囲った部屋など）。
  データから自動で分かること（通れるか・上を歩くと消えるか・全マップで使われた回数・よく使われているマップ・よく上下左右に来るパーツ）も一緒に返します。
  ファイルが無い時は、管理ページと一緒に配る `web/account/parts-dex-seed.json`（よく使われている約 230 個の名前と見本 3 つの下書き）から始めます。
  管理ページで直すか、書き込みもできるキーの AI が `sbo_parts_dex_update` で直します。
- **配置案**（`SBODATA/SboWebMapPlans.json`）… AI が `sbo_plan_save` で保存したマス目（最大 128×128・200 件まで）。
  管理ページの「配置案」で、パーツ番号・マス目の線・書き込み（marks）を重ねた画像で見られ、PNG と番号の表（タブ区切り）で持ち出せます。
  気に入った案は、それを見ながら管理者ウィンドウで実際に置きます。

AI への頼み方の例:「sbo_parts_dex で水・壁・床のパーツを調べて、見本も参考に、港町の市場の配置案を 40×30 で作って sbo_plan_save で保存して」

HTTP では `/api/data/parts/dex`・`/api/data/parts/samples`・`/api/data/parts/update`・`/api/data/plans/save`・`/api/data/plans/list`・
`/api/data/plans/get`・`/api/data/plans/delete`（引数は MCP のツールと同じ）。

## ステージング

ステージングはサイト全体に Basic 認証がかかっていますが、AI のツールは `Authorization` ヘッダーに AI 用キーを入れるのでぶつかります。
そのため `/mcp` と `/api/data/*` だけは Basic 認証の外に置いています（AI 用キーで守られます。`deploy/staging/sbo2003.caddy.template`）。
