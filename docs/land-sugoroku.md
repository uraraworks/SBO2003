# 土地取りすごろく（周回型・段階 1）

既存のサブゲーム「すごろく」に足した新しいルール種別です。外周 28 コマの盤を周回し、空き地を買い、他人の土地では通行料を払い、総資産で勝負します。**1 コマ＝マップの 3×3 マス**で、盤全体は 24×24 マス（用語：「コマ」＝盤の 1 区画、「マス」＝地図の 1 マス）。
提案は `_work/sbo2003-land-sugoroku/提案.md`。この文書は **段階 1**（2 人で、周回・購入・通行料・手番の時間切れ・盤の重ね描き・帯HUD まで）の仕様です。
地方そろえ・開発 3 段階・四隅の効果・冒険イベント（段階 2）、3〜4 人・管理画面での盤の編集（段階 3）、称号・記録・CPU 代行（段階 4）は未実装です。

## 遊び方

1. すごろくの受付マスで、すごろくの参加アイテムを使い、コマンドで「参加」を選ぶ（既存のすごろくと同じ。参加は 60 秒募集・2 人以上で開始。「観戦」を選ぶと盤の外から見られる）。土地取りは遊べるのは 4 人まで（段階 1 は 2 人で確かめている）。
2. 開始すると全員が盤の「スタート」のマスに立つ。順番に、**自分の番にコマンドを開いて「サイコロを振る」**。サイコロは 2 個（2〜12）で、出た目の合計だけキャラが時計回りに歩く。**1 コマ進むごとに普通の歩き速度で 3 歩**（コマの中央から次のコマの中央まで。曲がり角のコマでも中央を通るので、直角に曲がる）。最大 12 コマ＝36 歩で約 11 秒かかる。
3. 止まったコマで:
   - **空き地**：「○○を 120G で買いますか？」と「はい・いいえ」の確認が出る。買うと自分の土地（色枠がつく）。お金が足りない時は聞かれずに次の人へ。
   - **他人の土地**：通行料を持ち主へ払う。**払えなければ脱落**（残りの土地は銀行＝空き地に戻る）。
   - **自分の土地**：何も起きない。
   - **四隅のコマ**：スタート＝周回ボーナス / 渡し舟小屋＝次の手番が 1 回休み / ギルド酒場＝段階 1 は何もしない / 迷いの森＝3 コマ戻る（戻る途中でスタートは通らず、戻った先の効果も起きない。戻る時は歩かずフェードで移る）。
   - **同じコマに複数人が止まる時**は、後から止まった人が 3×3 の空いている四隅へ寄って立つ（先にいた人はそのまま。通過中は中央を歩く）。
4. お金は専用の **G**（初期 1500G。実際のゴールドとは無関係で、持ち出し・持ち込みなし）。スタートを通る・止まるたびに周回ボーナス 200G と周回数 +1。
5. **手番は 30 秒**（サイコロ待ちと購入の返事待ち。駒が歩いている間は数えない）。サイコロを振らずにいると自動で振られ、「買いますか？」に答えないと「やめる」になる（時間切れの文言がメッセージに出る）。
6. 終わり方:
   - 誰かが **12 周** に届くと、その周の全員の手番が終わった所で終了。**総資産（現金＋土地の値段）が最大の人の勝ち**（同点は引き分け）。
   - 通行料が払えず脱落、または切断・退出・マップ移動で抜けた人が出て、**1 人だけ残ったらその人の勝ち**（切断・退出・マップ移動も脱落。土地は銀行へ）。
   - 終わると結果をメッセージに出し、8 秒後に全員が受付へ戻る。報酬は無し。
7. 脱落（破産）した人は受付へ戻って観戦者になり、最後まで盤の状態を見られる。

20 分の時間制限は段階 2 です（段階 1 は 12 周のみ）。

### 画面（クライアント）

- 盤の各コマ（**96×96 ドット＝3×3 マス**）の上に重ね描きする（落ち物パズルの重ね描きと同じ作り。キャラは重ねの上に立つ）。
  - **上段**（32 ドット）：土地名と値段。名前は **短縮せず 1 コマに収まれば全名**、収まらなければ短い名前。四隅のコマ（スタート・渡し舟小屋・ギルド酒場・迷いの森）も同じ大きさで名前を出す。**四隅のコマは、駒（中央と四隅のマスに立つ）が名前に重ならないよう、名前を上・中・下の 3 段のうち駒の立つマスが一番少ない段に出す**（誰もいなければ中段。同数なら 中段→下段→上段。実際のキャラの位置で決めるので、駒が来る・去ると段が移る）。通常の土地コマの上段は今のまま。
  - **中段**（32 ドット）：持ち主の色の帯（持ち主がいれば帯を塗り、コマの枠も持ち主の色で太くなる）。1 人目から赤・青・緑・黄。中央のマスが駒の代表位置。
  - **下段**（32 ドット）：開発段階の場所。段階 1 は未開発なので、3 段階ぶんの空の枠を薄く出すだけ（段階 2 で使う）。
- 画面は 15×15 マス（480×480 ドット）なので盤全体（768×768 ドット）は見えない。歩く人（自分）についてスクロールする。
- 画面の上の中央に帯HUD：題・手番の人・残り秒（10 秒以下は赤）・出目、その下に各自の色・名前・所持金・周回数・土地数（休み中は「休」）。手番の人に `>`、自分に「(あなた)」。脱落は灰色の「脱落」。自分の番でサイコロ待ちの間は「あなたの番です。コマンドでサイコロを振る」。終了後は勝者に「勝ち」。
- 帯HUD の右端に **28 コマの小さな一覧**（盤と同じ並びの輪。1 コマ＝8 ドットの四角）。持ち主の色で塗り、空き地は灰色、四隅は金色。駒の位置は人の色の点（黒い縁つき。同じコマに複数人いれば四隅に分かれる）。盤全体が見えなくても全体の状況と自分・相手の位置が分かる。
- 観戦者にも同じ状態（帯・一覧・重ね描き）が届く（途中から観戦に来た人にも）。
- サイコロの出目・購入・通行料などはシステムメッセージにも出る。
- 既存のすごろくと同じく、参加中（観戦者を除く）は歩けない・ミニゲーム中のショートカットは止まる（`abySubStatus`）。

## データ投入手順

### 1. マップに盤を作る

実マップに **24×24 マス**の外周の輪（1 コマ 3×3 マスを、1 辺 8 コマ・全体で 28 コマ並べた輪。幅 3 マスの道）を作る。駒は実キャラがマスの上を歩くので、盤のマスは地面として歩ける・盤の外へ出ないこと。キャラの位置はサーバーが決めるので壁判定は使わない。内側（輪の中の 18×18 マス）は自由。マップは盤の左上＋24 マスが収まる広さが要る（旧仕様の 8×8 マスの盤は使えない）。

### 2. 管理画面でサブゲーム（すごろく）を作る

既存の管理画面（管理者ウィンドウのサブゲーム編集）でマップごとのすごろくを設定する。

| 項目 | 土地取りでの使い方 |
|---|---|
| マップ | 盤を置いたマップ |
| 参加受付 X・Y | 受付マス（既存どおり。参加アイテムを使う場所。盤の外でも中でもよい） |
| ルール | **「土地取り(周回)」**（`byRule` = 2） |
| 最大参加人数 | 2〜4（土地取りは 4 まで。段階 1 は 2 で運用） |
| イベント | **スタート** イベントを **盤の左上の角のマス（24×24 マスの左上隅）**（座標が 0 でないこと）に 1 つ置く。これが盤の左上のマップ座標で、そこから 24×24 マスを使う |
| パーツ | 土地取りでは使わない（盤はマスの座標で決まり、パーツ ID では決まらない） |

スタートイベントの座標の扱い（旧仕様から変わる所）:
- イベントの位置は **スタートのコマ（3×3 マス）の左上のマス**。旧仕様は「スタートのマス 1 つ」だったので、盤の左上を指す点は同じ。3 倍の広さでも設定し直すのは**イベントを置く位置が盤の左上であること**だけ（広がるのは右・下方向）。
- 参加する人は、参加を受け付けると既存のすごろくと同じく **このイベントのマスへ飛ばされる**（＝スタートのコマの左上の隅）。ゲームが始まると、全員がスタートのコマの四隅（参加者の番号順に左上・右上・左下・右下）へ移る。
- **START イベントの座標は盤の左上のまま（3×3 でも問題なし）**。中央マス基準にはしていない（中央基準にすると盤の左上が (X-1, Y-1) になり、マップの端の盤で座標が負になり得るため）。40×40 のテスト盤（左上 (6,6)）で、盤の位置・スタートのコマ・全員の四隅への移動が合うことを確かめた。
- 受付 X・Y は参加アイテムを使う場所だけで、盤の中でも外でもよい（盤とは関係なく決められる）。

盤のコマとマップ座標の対応（盤の左上 = (X, Y) の時。`gx`・`gy` は盤の中のコマの格子位置 0〜7）:

```
コマの格子位置（8×8。外周だけを使う）          1 コマの中（3×3 マス）
(X, Y)  → 0   1   2   3   4   5   6   7 ← 渡し舟小屋     ┌───┬───┬───┐
         21(迷いの森)                    8                │左上│   │右上│
           ・・・                         ・               ├───┼───┼───┤
         (左下) 14(ギルド酒場)(右下) ←  14               │   │中央│   │   中央＝コマの代表位置
                                                         ├───┼───┼───┤
                                                         │左下│   │右下│   四隅＝同じコマに複数人いる時の立ち位置
                                                         └───┴───┴───┘
```

- コマ `n` の格子位置 `(gx, gy)`:
  - 上の辺（左→右）: コマ 0〜7 = (0..7, 0)
  - 右の辺（上→下）: コマ 8〜14 = (7, 1..7)
  - 下の辺（右→左）: コマ 15〜21 = (6..0, 7)
  - 左の辺（下→上）: コマ 22〜27 = (0, 6..1)
- マップ座標: **中央のマス = (X + gx×3 + 1, Y + gy×3 + 1)**（コマの代表位置）。四隅のマス = (X + gx×3 + {0 または 2}, Y + gy×3 + {0 または 2})。
- 四隅のコマ: 0=スタート・7=渡し舟小屋・14=ギルド酒場・21=迷いの森。ほかの 24 コマが土地。
- 例: スタート（0）の中央 = (X+1, Y+1)、右上（7）の中央 = (X+22, Y+1)、右下（14）の中央 = (X+22, Y+22)、左下（21）の中央 = (X+1, Y+22)。

コマ番号 → 格子位置は `LandCellOffset`、コマ → マスの位置は `LandCellTile`、四隅のコマの種類は `LandCornerKind`（`common/LandSugoroku.h`）。

コマ 1〜6・8〜13・15〜20・22〜27 に、上の順で並ぶ（辺ごとに 2 地方。安い方から時計回り）。

**差し替え**（ガルムーン・ロウェルの正式名、値段の調整）は、サーバーのデータフォルダに `SBODATA/SboDataLandBoard.tsv` を置く。ゲームを始めるたびに読み直すので、サーバーの再起動は要らない。ファイルが無い・壊れている時は標準の表（壊れている時はサーバーのログに `[land] ... 標準の土地表で遊びます` が出る）。

タブ区切り（UTF-8。`#` で始まる行と空行は無視）。1 行 1 コマ、書かなかったコマは標準のまま:

```
# コマ番号	種類	地方	名前	短い名前	値段	通行料
13	town	4	ガルムーン本町	ガ本	200	40
21	forest	0	迷いの森	森	0	0
```

- 種類は `start` / `ferry` / `tavern` / `forest` / `town`。**四隅のコマ（0・7・14・21）は決まった種類のまま**（ほかを四隅の種類にしたり、四隅を土地にするとファイルごと無効になる）。
- 土地の値段・通行料は 1〜60000。通行料が値段より高くてもよいが、遊びやすいのは 1/5 前後。
- 名前は 39 バイトまで（全角 13 文字）、短い名前は 7 バイトまで（**全角 2 文字**）。盤の上には、全名が 1 コマ（96 ドット。12 ドットの字で全角 7〜8 文字ぶん）に収まれば全名を、収まらなければ短い名前を出す。長いと文字の途中で切れないよう欄に収まる所まで。
- 地方は 0〜7（段階 1 は色分けの下地で、遊びには影響しない。段階 2 の「地方そろえ」で使う）。
- 読み込みと検査は `LandBoard::LoadTsv`・`Validate`（単体テストあり）。

## 素材（ドット絵）の使い方

画像は `SboGrpData/grp/land_cells.png`（コマ絵）と `land_ui.png`（UI 部品）。座標表は `docs/land-sugoroku-assets.md`。**どちらも RGBA の PNG**（透明は完全な透明か不透明の 2 値）。

- **組み込み**: `SboGrpData/SboGrpData.rc` に `IDP_LAND_CELLS`・`IDP_LAND_UI` を足してある（Windows の DLL もブラウザ版のリソース表 `tools/web/gen_resources.py` も `.rc` を読むので、これだけで両方に入る）。クライアントは `ReadData`（`SboCliMain.cpp`）で `g_pDibLandCells`・`g_pDibLandUi` に読む。
- **読み込み**: `ReadGrpData2` は従来パレット形式（256 色）だけを読んでいたので、RGBA の PNG も読めるようにした。**透明のドットは黒 (0,0,0)＝カラーキー**にし、絵の中の本当の黒はほんの少し明るくして（RGB を 1 以上に）キーと区別する。パレット形式の PNG の読み方は変えていない。
- **フォールバック**: `DrawLand` は `LandArtReady`（2 枚とも読めていて大きさが 672×384・256×128 のとき真）で絵を使うか決める。読めない・大きさが違う時は、これまでの単色と文字だけの描き方のまま（壊れない）。
- **コマ**: コマ番号 `i` の絵は `land_cells.png` の `(i%7)*96, (i/7)*96` の 96×96。コマの背景に透明つきで描く（絵の四隅は丸く、地面が見える）。その上に、土地は上段へ暗い帯（アルファ 140）＋名前と値段、持ち主がいれば中段へ持ち主の色の薄い帯（70）と色枠 2 ドット、下段へ薄い暗い敷き。四隅のコマ（0・7・14・21）は絵の上に、名前の行だけ暗い帯を敷く（名前を出す段の選び方は従来どおり）。
- **旗・開発枠**: 持ち主の旗（`land_ui.png` の `(プレイヤー番号*16, 24)`・16×16。1 人目から赤・青・緑・黄）をコマの左下の角（コマの左上から (6,74)）に。開発段階の下段は 16×16 の空の枠を 3 つ、右寄せで薄く出すだけ（段階 1 は未開発）。段階 2 で宿 `(64,24)`・店 `(80,24)`・城 `(96,24)` のアイコンを同じ場所に描く。
- **帯HUD**: 9 スライス枠（24×24・四隅 6 ドット。`LandUiFrame`）で描く。通常は `(0,0)`、**自分の手番でサイコロ待ちの間**は明るい縁の `(24,0)`。**枠の中央は塗らず**（`LandUiFrame` は縁だけ）、文字の描画側で枠の内側（縁 6 ドットを除く）に `W32ShadeSpan` で `RGB(34,35,55)`・濃さ 170 の**半透明**を敷く（背景のマップの草やコマが透けて見える）。濃さは `DrawLand` の `nAlpha`。素材がある時は 1 行目を 24 ドットの高さにし、各自の行の頭に色の三角ポインタ（`(プレイヤー番号*16, 40)`・16×16。従来の色の四角の代わり）を出す。移動中は 1 行目の右端に出目のサイコロ 2 つ（24×24・`((目-1)*24, 56)`）を出す（従来の「出目 a+b」の文字の代わり。システムメッセージにも従来どおり出る）。
- **観戦者**: 同じ `CMD_LANDSTATE` を受けて同じ `DrawLand` で描くので、観戦者（脱落した人・途中から観戦に来た人）にもコマ絵・旗・帯・サイコロが同じように出る（自分の手番の明るい縁と「(あなた)」は出ない）。
- **手番の人の頭上のポインタ**は入れていない（キャラ（実キャラ）の座標とプレイヤーの対応が帯の行からは取れないため）。帯の一覧の行頭に使っている。

## 仕組み（読む人向け）

- **状態機械**: 参加募集（既存の JOIN。60 秒）が終わると `SubLand_Start`。その後は `SubGameProc_SUGOROKU` が土地取りの時だけ `SubLand_Proc` に任せ、`LandGame` の段階（サイコロ待ち → 移動中 → 購入待ち）を既存の状態値（WAIT / MOVE / `SUBGAME_SUGOROKU_STATE_LANDBUY`）に写す。
- **駒の移動（コマ → マスの歩き）**: ルール（`LandGame::Step`）は 1 コマ単位のまま。サーバーは、次のコマの中央までの 3 マスを **予定（`aWalkX`・`aWalkY`）に積み**、`LandPump` が `LAND_WALK_MS` ごとに 1 マスずつ `CHARPOS` で送る（既存すごろくの `SubSugoroku_Move` と同じ送り方）。3 歩目の時間が過ぎてから `Step` を呼び、そのコマの処理（購入・通行料・四隅）を行う。つづけて歩く時は間をあけず次のコマの 1 歩目へ入る。四隅に立っていた人は、まず中央へ戻ってから歩く。迷いの森で戻される時だけ `LandJump`（フェード）。移動中は制限時間を見ない（最大 36 歩＝約 11 秒。サイコロ・購入の 30 秒はそのあとから数え直す）。抜けた人の歩きの予定は捨てる。
- **ルールと進行の分担**: `LandGame` は「起きたこと」を `aEvent` に積む。サーバーの `LandDrain` がそれをメッセージ（`SubSugoroku_Msg`）にして全員へ送り、`CMD_LANDSTATE` を送り直す。時刻は `timeGetTime` を渡すだけ（`LandGame` は時計を持たない）。
- **サイコロ・購入**: 既存の `CMDSUBSUGOROKU_DICE`（`RecvDataProcSubGameSUGOROKU_DICE` が土地取りなら `SubLand_Dice` へ）と、新しい `CMDSUBSUGOROKU_LANDBUY`（`byData`=1 買う・0 やめる）。手番でない人・段階が違う時の要求は無視される。
- **購入の確認**: `CMD_LANDSTATE` の `byAsk` が付いた人（手番の本人）のクライアントが、既存の「はい・いいえ」確認ウィンドウ（`MakeWindowCONF`。番外編の「抜けますか？」と同じ作り）を出す。出てから 0.4 秒は決定を受け付けない（連打対策）。時間切れ・他の人の脱落などで `byAsk` が付かなくなると、クライアントは確認を閉じる。
- **離脱**: 切断・退出・マップ移動は既存の `SubSugoroku_RemoveAndMove` → `SubSugoroku_Remove` を通り、土地取りなら参加者の表から外した後に `SubLand_OnLeave`（`LandGame::Eliminate`）で脱落。1 人になれば勝ち。終了処理 `SubSugoroku_Quit` は `pLand`（進行の情報）を捨てる。
- **既存すごろくへの影響**: `byRule` が土地取りでない時は、状態機械・離脱・サイコロとも従来の処理のまま（差し込みは `byRule` と `pLand` の確認だけ）。`SUBGAME_SUGOROKUINFO` の末尾に足した `pLand` は保存しない（ゲーム中だけ持つ）。
- **管理画面**: ルールの選択肢に「土地取り(周回)」を足した（`aSugorokuRuleTbl`）。盤の編集・町名と価格のデータ API は段階 3。

## テスト

- **サーバーのテスト用の仕掛け**（`-DSBO_LAND_TEST` でビルドした時だけ有効。通常のビルドには入らない）: `cmake --preset mac-debug -DCMAKE_CXX_FLAGS=-DSBO_LAND_TEST` → `cmake --build --preset mac-debug`。データフォルダの `LandTest.txt`（1 行 1 指示）で、`D 出目1 出目2`（サイコロを振るたびに先頭の 1 行を使って消す。足りなければ乱数）・`LAPS n`（終了する周回数）・`GOLD 番号 G`（開始時の所持金）を指定できる。進行のメッセージはサーバーの標準出力に `[landtest] ...` で出る。元に戻す時は `-DCMAKE_CXX_FLAGS=` で作り直す。

- ルールの単体: `g++ -std=c++11 -O1 -I. tests/server/land_sugoroku_test.cpp -o /tmp/land_sugoroku_test && /tmp/land_sugoroku_test`（「一致」で OK。購入・通行料・周回ボーナス・渡し舟・酒場・迷いの森・脱落・1 人残りの勝ち・12 周終了と総資産・同点・制限時間・TSV の読み込み・乱数で多数回遊んでも整合が崩れないこと。コマ → マスの座標（中央は 3×3 の真ん中・となりのコマの中央とは 3 歩・四隅は中央や互いと重ならない）も確かめる）。
- サーバーの結合（`tests/server/run.sh` / `compare.sh` の `AW`）: 実サーバーのコードで、2 人が参加→開始→サイコロ→購入→通行料→時間切れの自動→抜けて脱落→終了までをモック通信で確かめる。`CMD_LANDSTATE` の送信数・システムメッセージ・既存のすごろくの観戦参加（G）が壊れていないことも見る。
