# 管理者画面の「元に戻す」

管理者ウィンドウで変えたデータを、**画面ごとに 1 回分ずつ** 元に戻せます。

## 使い方

1. 戻したい画面（例: アイテム一覧）を開いたまま、メニューの **編集(Z) → この画面の変更を元に戻す(U)** を選ぶ
2. 「「アイテム一覧」で3分前に〇〇さんが変えた 2 件 を元に戻しますか？」と聞かれるので「OK」を押す
3. 戻した結果が出て、その画面が新しい内容で開き直されます

- 何回でも続けて戻せます（1 画面につき新しい方から 50 回分まで覚えています）。
- 戻した後で「やり直す」はできません。
- 記録はサーバーのメモリだけにあります。**サーバーを再起動すると、それより前の変更は戻せません。**

## 「1 回分」のまとまり

- その時に開いていた画面ごとに記録します。たとえば「ステータス情報」の画面でステータステンプレートを変えた時は、
  「ステータス情報」の画面で戻します。
- 同じ人が同じ画面で **3 秒以内に続けて** 送った分は 1 回分にまとめます
  （職業情報の「送信」で全職業を送る・マップを塗る、など）。

## 対応している画面

| メニュー | 画面 | 戻せる変更 |
|---|---|---|
| マップ | パーツ | マップの塗り替え（マス単位） |
| マップ | マップ情報 | マップ名・BGM・初期位置・明るさなど |
| マップ | イベント情報 | イベントの更新（追加・削除は戻せない） |
| マップ | メッセージ | メッセージの更新 |
| マップ | 店情報 | 売り物・店のセリフ |
| キャラ | ステータス情報 | キャラのステータス・ステータステンプレートの更新 |
| キャラ | 所持アイテム情報 | 持ち物・装備 |
| キャラ | 所持魔法情報 | キャラの魔法・テンプレート |
| キャラ | ステータステンプレート情報 | ステータステンプレートの更新（追加したテンプレートは戻せない） |
| アイテム | 一覧 | アイテムの更新（新しく追加したアイテムは戻せない） |
| エフェクト | ふきだし・効果いろいろ | 更新 |
| その他 | 職業情報 | 職業（レベルアップ情報も）の更新 |
| その他 | 魔法情報・魔法利用者情報・装備職業情報 | 更新 |

対応していない画面（キャラ情報・アカウント・サブゲーム情報など）でメニューを選ぶと、その旨を案内します。
追加・削除は戻せません。イベントを削除すると、そのマップのイベントの記録は使えなくなるので消します。

## 上書きしないための確認

戻す前に、変えた対象が **記録した「変更後」のまま** かを確かめます。
そのあとでゲーム中の変化（HP・持ち物など）・ほかの管理者・API の変更が入っていたら、戻さずに
「そのあとで変わっていた」と案内し、その記録は消します。必要なら手で直してください。

キャラは欄が使い回されるので、名前も同じかを確かめます。

## 仕組み（開発向け）

サーバー側（`SboSvr/src/SboSvrAdminUndo.cpp`）で記録します。

- 管理者用のコマンドを処理する直前に、変わる対象（アイテム 1 件・マップの 1 マスなど）の今の状態を、
  **クライアントがそのデータを変える時に送るのと同じ形のパケット** にして取っておく。
  送信と受信で同じ形のコマンドは、`SendCmdXXX` が作る送信データを横取りして使う
  （`server/CUraraSockTCP_svr.cpp` の `SvrSendCaptureBegin` / `SvrSendCaptureEnd`）。
- 処理した後の状態も取っておき、変わっていなければ記録しない。
- 元に戻す時は、前の状態のパケットを管理者の操作として処理し直す（`RecvCmdReplayAdmin`）。
  反映・全員への通知は今ある受信処理がそのまま行う。
- クライアントは画面を切り替えた時に `CMD_ADMINUNDO`（`ADMINUNDO_SCREEN`）で開いている画面を知らせる。
  「元に戻す」は `ADMINUNDO_INFOREQ` → `ADMINUNDO_INFO`（確認）→ `ADMINUNDO_EXEC` → `ADMINUNDO_RESULT`。

新しく戻せるデータを増やす時は、`ParseKey`（届いたパケットから対象を読む）と
`BuildState`（対象の今の状態をパケットにする）に 1 つずつ足し、`AdminUndoDefaultScreen` で画面を決めます。

## API・MCP から使う

Node.js 側（`server/node/`）から、次の C の関数を呼べます（`Module._関数名`、文字列は UTF-8）。

| 関数 | 内容 |
|---|---|
| `SboAdminApplyPacket(ptr, size, source, screen)` | 管理者用コマンドのパケット（クライアントが送るのと同じ形）を処理し、「元に戻す」に記録する。`source` は案内に出す名前（例 `"API"`）、`screen` は記録する画面（`ADMINSCR_*`、0 ならコマンドからいつもの画面）。メッセージ・店はパケットの `dwTblID` のキャラのいるマップが対象。処理したら 1 |
| `SboAdminUndoListJson()` | 戻せる変更がある画面の一覧（JSON 文字列）。`[{"screen":10,"name":"アイテム一覧","count":2,"stepId":15,"text":"…"}]` |
| `SboAdminUndoExecJson(screen, stepId)` | その画面の最後の変更を元に戻す（`stepId` が 0 以外ならその変更の時だけ）。`{"ok":true,"count":1,"text":"…を元に戻しました。"}` |

API からの変更も管理者ウィンドウの変更と同じ記録に入るので、どちらからでも同じ画面の単位で戻せます。
画面の番号は `common/TypedefCommon.h` の `ADMINSCR_*` です。
