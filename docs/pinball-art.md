# ピンボールの盤の絵（差し替え絵）の素材仕様

ピンボールの盤は、いまは図形（線・円）で描いています。ここで決める PNG を置くと、図形の代わりにその絵で描きます。
**絵が無い・読めない・大きさが合わない時は、今までどおり図形で描きます**（壊れない）。当たり判定は絵に関係なく
`common/Pinball.h` の図形のままなので、絵は当たり判定に合わせて描きます。

- 台の遊び方・仕組み: `docs/pinball.md`
- Codex（絵を描く AI）への指示文は、テンプレートと一緒に渡す `codex-prompt.md`（この文書の内容を、Codex が読める形にまとめたもの）

## 置くファイル

| ファイル | 置き場所 | 大きさ | 中身 |
|---|---|---|---|
| `pinball_bg.png` | `SboGrpData/grp/` | **160×448**（`PB_W`×`PB_H`） | 背景（盤全体。壁・アーチ・斜め壁・床・飾り） |
| `pinball_parts.png` | `SboGrpData/grp/` | **128×96** | 部品のシート（ボール・ターゲット・バンパー・フリッパー） |

- 形式は **インデックスカラー（パレット）の PNG・256 色まで**（既存の `map01.png`・`system.png` などと同じ。RGB・RGBA・16 ビット・インターレースはゲームが読めず、図形に戻る）。色数が少ないと PNG は 4 ビットなどで保存されるが、それも読める。
- 大きさが違うと使われない（背景が 160×`PB_H` でない・部品が 128×96 より小さい）。`PB_H` や `PB_W` を変えた時は絵も作り直す。
- 画像はリソース `IDP_PINBALL_BG`・`IDP_PINBALL_PARTS` として読む（`SboGrpData/SboGrpData.rc`）。ブラウザ版は `tools/web/build.sh` が他の画像と同じく `.data` に入れる（`tools/web/gen_resources.py`。キャッシュも同じ扱い）。ファイルが無いとビルドは「図形で描きます」と知らせるだけで続く。
- Windows 版のリソース DLL（`SboGrpData.rc`）は、絵のファイルが無いとビルドが通らないので、`#ifdef SBO_PINBALL_ART` で囲んである。絵を置いたら、`SboGrpData` のリソースのプリプロセッサ定義に `SBO_PINBALL_ART` を足す（または絵を正式に入れる時に `#ifdef`・`#endif` の行を消す）。

## 色・描き方の約束（SBO らしさ）

- **透明は黒 (0,0,0)**。ゲームのカラーキーが純黒なので、絵の中で黒を使ってはいけない（透けて見える）。縁取りは **(16,16,32) くらいの暗い色**にする。`check_art.py` が「ほぼ黒」を教える。
- **半透明は使えない**（アンチエイリアスなし。ふちのぼかしも使わない）。ドットはくっきり。
- **16 ドット格子**：テンプレートの 16 ドットごとの格子に、部品・飾りの大きさと位置を合わせる。
- **2×2 ドットの太いピクセル**で描くと SBO の他の絵と並んだ時になじむ（既存の絵は 16×16 のマスを 2 倍に拡大して表示している）。背景は 80×224、部品シートは 64×48 の絵を、補間なし（最近傍）で 2 倍にして保存するとよい。座標が 2 の倍数なら、ガイドの位置（下の表）はそのまま使える。
- **限られた色数**：背景は 48 色・部品は 32 色くらいまでを目安にする（超えても動く）。同じ色・同じ縁取りを背景と部品で揃える。
- **黒縁取り**（暗い色の 1 ドット幅の輪郭）を、ボール・バンパー・ターゲット・フリッパー・壁に付ける。マップパーツ・キャラ絵と同じ見え方になる。
- 明るさ：背景は暗めの落ち着いた色にして、ボール（明るい）・バンパー・ターゲットが目立つようにする。

## 背景 `pinball_bg.png`（160×448）

盤全体を **(0,0)–(160,448)** に描く。画面には、窓（160×224）が上下に動いて、盤の一部が映る（下端の窓は y=224〜448、ボールを追って上へ動く）。つまり絵は 1 枚で盤の全体。

- 盤の外（壁の外・アーチの外）は透明（黒）にしておくと、後ろのマップが見える。壁の外側は 4〜8 ドットの縁（壁の太さ）まで描いてよい。
- 動くもの（ボール・ターゲット・バンパー・フリッパー）は**背景に描かない**（部品シートの絵が重なる）。ターゲット・バンパー・フリッパーの位置には何も描かないか、床の模様だけにする。
- 得点・残り球・ボールの溜め棒・「PUSH START」「GAME OVER」の文字は、ゲームが上に描く（絵に含めない）。
- 描く位置の基準は `common/Pinball.h` の定数。寸法の一覧は `tools/pinball/make_art_template.py` が `layout.json` に書き出す。主な値（既定）:

| もの | 位置（ドット。盤の左上が (0,0)） |
|---|---|
| 左の壁 `PB_WALL_L` | x=6（y=80〜396） |
| 右の壁 `PB_WALL_R` | x=156（y=80〜440） |
| 打ち出しレーンの仕切り `PB_LANE_L` | x=141（y=84〜440）。レーンは x=141〜156 |
| レーンの床 `PB_LANE_FLOOR` | y=440 |
| アーチ（上半円） | 中心 (81,80)・半径 75（球が触れる面）。盤の最上部 |
| 下の斜め壁 | 左 (6,396)→(38,424)・右 (141,396)→(109,424)。その下は軸の縦の壁（x=38・x=109。y=424〜458）で、2 つの間が穴 |
| フリッパーの軸 | 左 (38,424)・右 (109,424)。長さ 28、太さの半分 3 |
| 穴（球が落ちる線）`nDrainY` | y=446（球の中心がこれより下で落ちる） |
| 打ち出し待ちの球 | (148.5,436) |
| バンパー（円の半径 9） | 下側 (58,286)・(100,286)・(79,316)／アーチの下 (58,62)・(100,62)・(79,92)／中ほど (34,252)・(124,252) |
| ターゲット（長さ 16、太さの半分 2） | 下側 y=354（x=28〜44・66〜82・104〜120）／上側 y=150（同じ x） |

- **壁の絵の位置合わせ**：球は壁の線に**触れる**（球の半径 4 は線の手前で止まる）。壁の絵の「球に見える側の縁」を線の上に置き、壁の厚みは線の外側（盤の外側）へ描く。壁を線より内側へ描くと、球が壁の絵の上を通って見える。
- アーチも同じ。半径 75 の円の内側の縁が球の触れる面。
- 斜め壁は線の上側が面。穴（軸の間）は暗くして「落ちる」と分かるようにするとよい。

## 部品のシート `pinball_parts.png`（128×96）

| 番号 | 部品 | 左上 (x,y) | 大きさ | 中心／軸 | 使い方 |
|---|---|---|---|---|---|
| 1 | ボール | (0,0) | 16×16 | 中心 (8,8)。球の本体は半径 4 の円 | 球の中心に重ねる |
| 2 | ターゲット（立っている） | (16,0) | 32×16 | 中心 (16,8)。長さ 16・太さの半分 2 の線分＋丸い端 | 線分の中心に重ねる |
| 3 | ターゲット（倒れた） | (48,0) | 32×16 | 同上 | 倒れている間。低く暗く |
| 4 | ターゲット（光る） | (80,0) | 32×16 | 同上 | 当たった直後 0.18 秒 |
| 5 | バンパー（ふつう） | (0,16) | 32×32 | 中心 (16,16)。当たり判定は半径 9 の円 | バンパーの中心に重ねる |
| 6 | バンパー（光る） | (32,16) | 32×32 | 同上 | 当たった直後 0.18 秒 |
| 7 | 左フリッパー（下がり） | (0,48) | 48×48 | 軸 (12,24)。軸から長さ 28 で水平から**下へ 30°**。太さの半分 3 | 休み位置の姿 |
| 8 | 左フリッパー（上がり） | (48,48) | 48×48 | 軸 (12,24)。軸から長さ 28 で水平から**上へ 30°** | 上がり切った姿 |

- 空いている所（右端・下端）は透明（黒）のままにしておく（将来の部品用）。
- **フリッパー**：右のフリッパーは左の絵を左右反転して使う（描くのは左だけ）。途中の角度（5° ずつ 12 段階で動く）は、近い方の姿（段階 6 未満は 7、以上は 8）を、今の角度との差だけ軸のまわりに回して描く（最近傍。差は最大 30°）。だから絵は軸 (12,24) を中心に、先端へ向かって描き、軸の丸いキャップを軸の位置に置く。
- 部品の絵は、当たり判定の図形（テンプレートのガイド）の**輪郭にぴったり**重ねる。球やバンパーが絵より大きく／小さく見えると、当たったのに触れていない・触れていないのに跳ねる、に見える。縁取りの 1 ドットはガイドの線の外側に出してよい（セルの中に収める）。

## 差し替えの手順

1. テンプレートを作る（寸法が `common/Pinball.h` から決まるので、台の形を変えたら流し直す）。
   ```sh
   python3 tools/pinball/make_art_template.py -o out/pinball-art
   ```
   Python 3・Pillow・C++ コンパイラ（g++ か clang++）が要る。出力（既定 `out/pinball-art/`）:
   - `pinball_bg_guide.png`（160×448）・`pinball_parts_guide.png`（128×96）：当たり判定の輪郭・格子・番号を薄い色で重ねた下敷き
   - `pinball_bg_guide_x3.png`・`pinball_parts_guide_x6.png`：人が眺める用に拡大したもの
   - `pinball_bg_empty.png`・`pinball_parts_empty.png`：ガイド無しの空版（透明＝黒のインデックスカラー。この上に描くと形式がそのまま使える）
   - `layout.json`：寸法の一覧
2. ガイドを見ながら、空版（またはガイドを下のレイヤーにして、ガイド無しのレイヤーに描いて書き出す）で絵を描く。
3. `pinball_bg.png`・`pinball_parts.png` の名前で保存して、形式を調べる。
   ```sh
   python3 tools/pinball/check_art.py pinball_bg.png pinball_parts.png --preview out/pinball-art/preview.png
   ```
   `preview.png` は、描いた背景の上に当たり判定のガイドを重ねたもの（壁・バンパーの位置のずれを見る）。
4. 2 つを `SboGrpData/grp/` に置く。
5. ブラウザ版をビルドして見る。
   ```sh
   tools/web/build.sh && tools/server/build.sh
   tools/server/run.sh          # 別の窓で。ブラウザは out/web/dist を配信するページで開く（web/README.md）
   ```
   ピンボールの台（台詞が `@i` の NPC）の席に座り、次を見る：背景・バンパー・ターゲットの位置が当たり判定と合っている／球を打ち上げると窓が上へ動いて上の絵が出る／ターゲットが倒れる・光る／フリッパーが動く（左右）／待機中の台（座らず近くを歩く）／ゲームオーバー。
   絵が出ずに図形のままなら、形式（`check_art.py`）か大きさを疑う。
6. 絵を変えたら、ブラウザのキャッシュ（`.data` を IndexedDB に持っている）は中身が変わると自動で入れ替わる。

## 作りの要点（開発向け）

- 読み込み：`SboCliPinball.cpp` の `GetPinballArt`（初めて描く時に 1 回）。`ReadGrpData2`（`SboCliMain.cpp`）で読む。8 ビットのパレット PNG 以外は読まずに空の絵を返す（RGB の PNG を置いても落ちない）。
- 描画：`SboCliDrawScreen.cpp` の `DrawPinballOne`。背景は窓が映している範囲（`nCamY`〜+224）だけ写し、部品は当たり判定の位置を中心に写す。窓の外には描かない（切り取り）。フリッパーだけは `PbArtBltRot` で回して描く。部品シートの並びは `SboCliPinball.h` の `PBART_*`（テンプレート作成スクリプトも同じ値を読む）。
- 当たり判定・物理・通信は絵と無関係（サーバーは絵を知らない）。
- 後で足せるもの：スリングショット・レーンのプランジャー・飾りなどの部品は、シートの空いた所（右・下）にセルを足し、`PBART_*` と描画を足す。台ごとに絵を変える（台のデータ化）時は、リソース名を台の番号で分ける。
