# ダンジョン生成（ディアブロ1式）

ディアブロ1（devilutionX）の生成方式を参考にした、ランダムダンジョンの作り方です。
管理ページ /admin の「ダンジョン生成」タブで **テーマの登録** と **お試し作成** ができます。
ゲームの中では、サブゲーム「ダンジョン」（気まぐれダンジョン）にテーマ番号を入れると、作り直しのたびにそのテーマで作ります（下の「ゲームに入れる（サブゲーム「ダンジョン」）」）。
討伐チャレンジにはまだつながっていません。

元になった調査と実装は SBOP2 の `docs/dungeon-generation-diablo1-reference.md` と `SboSvr/src/MapGen/` です。

## 全体の流れ

1. **骨組みを作る**（C++ `SboSvr/src/DungeonGen/`）: 「床・壁・出入口」など意味だけの格子と、部屋の一覧・部屋どうしのつながりを作る。
2. **絵を当てる**（同じく C++）: テーマ（9分割の部屋・壁・飾り）を使って、格子をマップパーツ番号に置き換える。
3. **見る**（/admin）: 結果をパーツの絵で表示する。

骨組みと絵当ては、あとでゲーム内でも同じ C++ をそのまま使う。

## 作り方（algo）

| 番号 | 名前 | 中身 |
|---|---|---|
| 1 | L1 聖堂 | 通路なし。部屋の辺にそのまま次の部屋をくっつけて生やしていく（本家 GenerateRoom 寄り）。隣の部屋とは壁を共有し、共有した壁に広いアーチ・ときどき扉・まれに壁ごと抜いて広間にする |
| 3 | L3 洞窟 | 真ん中から 3〜4 マスのかたまりを生やし、縁を半々で床にする（SBOP2 MapGenCaveL3 の移植） |

L2 地下墓地・L4 地獄はあとで足す（番号 2・4 を空けておく）。

## 骨組みの格子（セルの値）

| 値 | 意味 |
|---|---|
| 0 | 何もない（外側・岩の中） |
| 1 | 床 |
| 2 | 壁の天井（上段） |
| 3 | 壁の側面（床に面した手前の面） |
| 4 | 壁（その他：縦の壁・下側の壁など） |
| 5 | 出入口の床（アーチ・壁を抜いた所） |
| 6 | 扉 |
| 7 | パターンのマス（固定パターンの部屋の範囲。床か壁かは分からないので、`theme` がある時だけ出る。色表示は「パターン」として別の色に） |

### パターンのマス（7）の扱い

- 全床連結・床の数え方では、固定パターンの範囲のうち **外周を除いた中を、1 つの床のかたまり** とみなす（床の数にも中のマス数を足す）。
- 外周は、L1 では通れない扱い（出入口の穴＝値 5・6 が開いた所だけが入口）。L3 では、外側の隣が床なら出入口として通れる扱い。
- 部屋一覧には固定パターンの部屋も入る（`fixed` = 1、`tpl` = 使ったパターンの番号）。

### L1 の部屋の形

- 部屋の外枠 `[x, y, w, h]` は壁を含む。上の壁は 2 行（天井＋側面）、左右の壁は 1 列。下の壁はテーマの `bottomRows` で決まる（下記）。
  - `bottomRows` 1（既定）: 下の壁は 1 行（天井だけ）。上下に並ぶ部屋は 1 行重ねる（上の部屋の下の行＝下の部屋の天井の行。出入口は、この行と下の部屋の側面の行の 2 行を抜く）。
  - `bottomRows` 2: 下の壁は 2 行（天井＋側面）。上下に並ぶ部屋は **2 行** 重ねる（上の部屋の下 2 行＝下の部屋の上 2 行）。素の絵でも、いちばん下の部屋の外側に面した下の壁を含め、下 2 行は天井（2）＋側面（3）。
  - 9分割の部屋（固定パターン以外）で、下の切れ目から下が 2 行以上ある部屋が 1 つでもあれば、`bottomRows` が 1 でも 2 として作る（1 行重ねだと、つなぎ目の壁が途切れるため）。
- 左右に並ぶ部屋は、どちらでも 1 列を共有する。
- 部屋の重なりは「上下はちょうど下の壁の行数ぶん（1 か 2 行）、左右はちょうど 1 列」だけ許す。
- 中の床の高さは `h - 2 - bottomRows`。2 行の時は床が 1 行減るので、部屋の最小（`roomMin`）は `3 + bottomRows`（1 行なら 4、2 行なら 5）以上に切り上げる。
- 部屋どうしが重なった壁のマス（つなぎ目）は、9分割の部屋を描いた後で、どの部屋の床に面しているかで持ち主を決め、その部屋の 9分割の同じ位置の絵で描き直す。強い順に「下が床（側面）」「下が出入口（側面。縦の壁をくり抜いた上）」「どれかの部屋の左右の列（縦の壁。下の壁の行は除く）」「2 つ下が床（上の縁）」「左右が床（横の壁）」「上か 2 つ上が床（下の縁）」。どれでもなければ天井（`wallTop`）。
- 固定パターンの部屋（外枠を含む）には飾り（`decos`）を置かない。
- 9分割の部屋は上の切れ目より上を 2 行（天井＋側面）にそろえる（管理画面で違う時に注意を出す）。1 行にすると 2 行目が床の絵でも通れない壁になる。
- 入口・ボス用の 9分割の部屋が無いテーマでは、入口・ボス部屋にもふつうの部屋の絵を使う。
- 入口用（`kind` 2）の 9分割の部屋に入口の印（`entryX`,`entryY`）があれば、伸ばした入口の部屋の同じ所（四隅はそのまま、伸ばした所は割合で）を start にする。床でなければ部屋の中央のまま。
- 出入口: 共有した壁の上で、横の壁なら 2 行ぶん（`bottomRows` 2 でも、重なった 2 行をそのまま）、縦の壁なら 1 列ぶんを、幅 `archMin`〜`archMax` マスだけ抜く。出入口パターン（`dir` 0。共有壁は 2 行で、パターン自体は `off` で上下にはみ出せる）・扉・壁ごと抜くも同じ 2 行。扉（パターン無し）は幅 1 マスで、扉の絵は下の側面の行だけ（上の天井の行は出入口の床 `arch`）。縦の壁の扉も高さ 1 マス。
- 固定パターン（`fixed`）・ボス・入口は、テンプレートの大きさそのままで同じ決まり（下 `bottomRows` 行が壁）として扱う。固定パターンは `h >= 3 + bottomRows` が必要。
- 骨組みのセル値は、`bottomRows` 2 の時、部屋の下 2 行を 2（天井）・3（側面）にする。部屋の `bot`（下の壁の行数）が部屋一覧に入る。

## テーマ（SBODATA/SboWebDungeonThemes.json）

```json
{
  "themes": [
    {
      "id": 1,
      "name": "聖堂",
      "algo": 1,
      "floor": [101, 102],            // 床（くじで混ぜる。先頭ほど出やすい…ではなく均等）
      "wallTop": [7],                 // 壁の天井（上段）
      "wallFace": [6],                // 壁の側面
      "wallFill": [7],                // その他の壁
      "void": 0,                      // 何もない所（0 = 塗らない）
      "arch": [101],                  // 出入口の床
      "archV": [],                    // 縦の壁の出入口の床（空 = arch と同じ）。パターン無しの縦の穴に使う
      "door": 0,                      // 扉のパーツ（閉じた絵。0 = 出入口の床と同じ）
      "doorOpen": 0,                  // 開いた扉の絵（ゲームの扉イベント用。0 = 扉イベントを置かない＝通れる出入口のまま。お試し作成では使わない）
      "dark": 0,                      // 暗さ（0〜100。0 = マップの設定のまま。1 以上ならダンジョンの範囲だけこの暗さにして、範囲の外＝外の入口は明るいまま）
      "entry": 0,                     // 入口の絵: start のマスに 1 枚だけ置く（0 = 置かない）。飾りは置かない
      "goal": 0,                      // ゴールの絵: goal（ボス部屋の真ん中）のマスに 1 枚だけ置く（0 = 置かない）
      "params": { "roomMin": 6, "doorRate": 20 },  // ゲームで使う生成の設定（w・h・seed 以外。省いた項目は既定値。下の「生成の設定」の表）
      "bottomRows": 1,                // L1: 部屋の外枠の下の壁の行数（1 = 天井だけ / 2 = 天井＋側面。既定 1。上下の部屋は同じ行数ぶん重なる）
      "rooms": [                      // 9分割の部屋（L1 用）
        {
          "name": "柱の広間",
          "kind": 0,                  // 0 = ふつう / 1 = ボス部屋用 / 2 = 入口の部屋用
          "w": 9, "h": 8,
          "cells": [ /* w*h 個のパーツ番号（左上から行ごと） */ ],
          "cutX": [1, 8],             // 縦の切れ目 2 本（左の列 = 0..cutX[0]-1、真ん中 = cutX[0]..cutX[1]-1、右 = cutX[1]..w-1）
          "cutY": [2, 7],             // 横の切れ目 2 本
          "fixed": false,             // true なら 9分割で伸ばさず cells をそのまま置く（下の「固定パターン」）
          "entryX": -1, "entryY": -1, // パターン内の出てくる位置（-1 = 無し）。-1〜w-1 / h-1
          "src": { "map": 53, "x": 10, "y": 20 }   // どこから取ったか（任意のメモ。管理画面では空の格子に描くので付かない）
        }
      ],
      "openings": [                   // 出入口パターン（L1 用。最大 50 件）
        {
          "name": "柱つきアーチ",
          "dir": 0,                   // 0 = 横の壁（共有壁は天井＋側面の 2 行） / 1 = 縦の壁（共有壁は 1 列）
          "type": 1,                  // 1 = アーチ / 2 = 扉 / 3 = 壁ごと抜く
          "w": 6, "h": 4,             // dir 0 は h >= off + 2、dir 1 は w >= off + 1（自由）
          "off": 1,                   // 共有壁に当たる行（dir 0: 天井の行。次の行が側面）／列（dir 1）。既定 0
          "cells": [ /* w*h 個のパーツ番号。扉は閉まった絵。0 = 透明（そのまま） */ ],
          "cellsOpen": [],            // 扉だけ。同じ大きさの開いた絵（無ければ空）
          "hole0": 2, "hole1": 4,     // 通れる範囲（dir 0 なら列 2..3、dir 1 なら行）。それ以外は両脇の柱・枠（壁の上に乗る）
          "cut0": 2, "cut1": 3        // 省略/-1 = 伸ばさない。あれば向きに沿った軸（dir 0 は列、dir 1 は行）の 3分割の切れ目で、hole0 <= cut0 < cut1 <= hole1
        }
      ],
      "decos": [                      // 柱・飾り（あとで中身を増やす）
        { "name": "たいまつ", "w": 1, "h": 1, "cells": [824], "on": 3, "rate": 20, "max": 8 }
      ]
    }
  ]
}
```

- `on`（飾りを置く所）: 1 = 部屋の床の真ん中あたり（壁から 1 マス離す）、3 = 壁の側面。
- 9分割の当て方: 四隅はそのまま、上下の辺は横に繰り返し、左右の辺は縦に繰り返し、真ん中は縦横に繰り返す。
  繰り返しが割り切れない時は途中で切る。部屋が四隅より小さい時は、その部屋には 9分割を使わず壁と床の素の絵にする。
- 9分割の部屋は大きさを見ずにくじで選ぶ（`kind` が合うもの）。合う部屋が無ければ素の絵（floor / wallTop / wallFace / wallFill）。
- 出入口・扉は部屋を描いた後に上から置く。

### 出入口パターン（`openings`）

L1 の共有壁に出入口を開ける時、壁の向き（`dir`）と種類（`type`。`doorRate` で扉、`openRate` で壁ごと抜く、それ以外はアーチ）が合うパターンがあれば、くじで 1 つ選んで使う。
穴の幅は、`cut0`/`cut1` が無ければ `hole1 - hole0`（`archMin`/`archMax` より優先）の固定。両脇の柱・枠まで含めたパターン全体が、共有壁の上（両端の角を除く）に収まる位置にだけ置く。収まらないパターンは選ばず、1 つも無ければ今までどおり（`archMin`〜`archMax`、`arch`/`door`）。
絵は `cells` で上書きする（扉の開いた絵 `cellsOpen` はお試し作成では使わない。ゲームに入れる時の扉イベント用）。パターンの範囲（はみ出した行・列も含む）には飾り（`decos`）を置かない。

- **伸び縮み（`cut0`/`cut1`）**: 穴の幅 `aw` を `archMin`〜`archMax`（縦の壁は `vertArchMin`/`vertArchMax` があればそれ）からくじで選ぶ。ただし `aw >= (hole1 - hole0) - (cut1 - cut0) + 1`（真ん中が 1 以上）で、パターンが共有壁に収まる長さまで。パターンの軸方向の長さは `L = len + (aw - (hole1 - hole0))`（`len` は dir 0 なら `w`、dir 1 なら `h`）。伸ばした位置→テンプレートの位置は部屋の 9分割と同じ（左の `cut0` 列と右の `len - cut1` 列はそのまま、真ん中は繰り返し、縮める時は真ん中を減らす）。扉・壁ごと抜くパターンも同じ扱い。
- **共有壁の位置（`off`）**: dir 0 は `cells` の `off` 行目が共有壁の上の行（天井の行）、`off + 1` 行目が側面の行。dir 1 は `off` 列目が共有壁の列。壁の行・列の外にはみ出した部分（天井の上、側面の下の床、縦の壁の左右など）は絵だけ上書きし（0 は透明）、骨組み（歩けるか）は変えない。マップの外にはみ出す位置には置かない。
- `dir` 0 は `h >= off + 2`、`dir` 1 は `w >= off + 1`、`cells` の数が `w*h`、`hole0 < hole1` で範囲内、`cut0`/`cut1` は両方あるか両方無く `hole0 <= cut0 < cut1 <= hole1`、でないパターンは使わない。L3 は使わない。
- パターン無しの縦の出入口（`links[].vert` = 1）の床は `archV`（空なら `arch`）を使う。

### 固定パターン（`fixed: true`）

`fixed` のパターンは 9分割に使わず（`cutX`・`cutY` は無視）、`cells` をそのまま `w`×`h` で置く。`theme` がある時だけ効く。
外枠＝パターンの大きさ。壁の決まり（上 2 行・下 `bottomRows` 行・左右 1 列）はパターンの絵の側で描いておく。

- **L1・入口**: `kind` 2 かつ `fixed` のパターンがあれば、くじで 1 つ選び、最初の部屋をその `w`×`h` ちょうどで作る（他の部屋はそこから生やす）。共有壁の出入口の穴は固定パターンの壁にも開き、その所だけ出入口の絵で上書きする。start は `entryX`,`entryY`（無ければ床の中央）。
- **L1・ボス**: `kind` 1 かつ `fixed` のパターンがあれば、最後に「入口から一番遠い部屋」の隣にその大きさで生やすのを試す。置けなければ今までどおり（一番遠い部屋がボス部屋）。
- **L3・入口**: `kind` 2 かつ `fixed` のパターンがあれば、洞窟を作った後、地図の中心に近い床を中心にパターンを置く（範囲の洞窟は消す）。パターンの縁の床（テーマの floor・arch・door のパーツのマス。無ければ縁ぜんぶ）から洞窟の床へ最短で掘ってつなぎ、つながらない床は消して、全床連結を確かめる。start は `entry`（無ければパターンの中央）。
- 地図に収まらない・`cells` の数が合わない・`w`/`h` が 4 未満のパターンは使わない。ボスの固定パターンは L3 では使わない。

### 灯りの上書き表（`lights`）

- `lights: [{"wParts": 824, "byLight": 4}]`（最大8件、byLight 0〜7）。このテーマでだけ、パーツの「灯りの範囲」を上書きする。
- お試し作成の「暗くして見る」で使う。ゲームでは、作り直しのたびに、そのマップの「パーツの灯りの上書き表」（MAPINFO の aPartsLight、データ API では `map.partsLights`）へ書き込み、マップの送り直しでクライアントへ届ける。
  上書き表は「マップ全体の表」なので、ダンジョン専用のマップの前提。`lights` が空なら触らない。範囲外のパーツ番号・byLight が 7 を超える行は捨てる。

## 生成の設定（お試し作成の入力）

| 項目 | 既定 | 意味 |
|---|---|---|
| `w`, `h` | 40, 40 | 大きさ（8〜128） |
| `seed` | 0 | 0 ならランダム。結果に実際のシードが返る |
| `roomMin`, `roomMax` | 6, 12 | L1: 部屋の外枠の一辺 |
| `floorMin` | 35 | 床が全体の何 % 以上になるまで作り直す（L1・L3） |
| `archMin`, `archMax` | 2, 4 | L1: 出入口の幅 |
| `doorRate` | 20 | L1: 出入口を扉にする % |
| `openRate` | 8 | L1: 共有した壁ごと抜いて広間にする % |
| `vertRate` | 100 | L1: 縦の壁（左右に並んだ部屋の共有壁）に出入口を開ける %。部屋を左右に生やす時と輪にする時の許可の確率。0 なら縦の壁には穴を開けず上下だけでつなぐ（全床連結は保つ）。壁ごと抜く（`openRate`）も、この確率を通った縦の壁にだけ |
| `vertDoorRate` | -1 | L1: 縦の壁の出入口を扉にする %（-1 = `doorRate` と同じ） |
| `vertArchMin`, `vertArchMax` | 0, 0 | L1: 縦の壁の出入口の幅（0 = `archMin`/`archMax` と同じ）。出入口パターン（`dir` 1）がある時はそちらが優先 |
| `loopRate` | 30 | L1: 生やした親以外の隣の部屋とも出入口でつなぐ % |
| `cutoff` | 25 | L3: かたまりを生やすのをやめる % |

### テーマの `params`（ゲームで使う設定）

テーマに `params` を持たせると、ゲーム（サブゲーム「ダンジョン」）はその設定で作る。`roomMin` `roomMax` `floorMin` `archMin` `archMax` `doorRate` `openRate` `loopRate` `cutoff` `vertRate` `vertDoorRate` `vertArchMin` `vertArchMax` だけを覚える（範囲は上の表。外れていると保存で断る）。
幅・高さはサブゲームのエリア（`byX1`〜`byX2`・`byY1`〜`byY2`）の大きさ、シードは作るたびに時刻なので、`params` には入れない。
管理画面では「今のお試し作成の設定をテーマに覚える」ボタンで、お試し作成の欄の値を入れる（保存するまで未保存）。テーマを開くと、`params` があればお試し作成の欄へ読み込む。

## ゲームに入れる（サブゲーム「ダンジョン」）

- サブゲーム（`subGame` の `byType` 3）の `detail.dwThemeID`（管理者ウィンドウでは「テーマ番号」）にテーマの `id` を入れる。0 = 今までの作り方。保存の列 `dwThemeID` は、0 でない時だけ書く（前の版のサーバーでも読めるように）。
- `detail.dwBuildNo`（作り直し番号。読むだけ・保存しない）は、テーマで作り直すたびに 1 ずつ増える。
- 作り直し（`MakeDungeonProc`。管理者の「作成」・人がいなくなった時）で、`dwThemeID` が 0 でなくテーマ（SBODATA/SboWebDungeonThemes.json。作り直しのたびに読み直す）が見つかれば:
  1. 今までと同じく、エリア内の人を外（`byStartX/Y`）へ出し、外の入口・出口の古いイベントを消す。
  2. エリア（`byX1`〜`byX2`・`byY1`〜`byY2`。生成の大きさは 8〜128 に収める。129 以上のエリアは左上の 128 まで生成し、残りは壁で塗る）の大きさで生成する（シードは時刻、`params` はテーマの）。
  3. 結果の絵をエリアのマスに書く。0 のマス（何もない所）は `void`、`void` が 0 なら `wallFill` の先頭で塗る。
  4. エリア内の古いイベントを全部消し、置き直す: 外の入口（`byStartX/Y`。絵は `wChipIDStart`）→ 生成の start へワープ、生成の goal のマス（絵はテーマの `goal`、無ければ `wChipIDGoal`）→ `byStartX/Y` へ戻るワープ、扉イベント（下）。中の入口（生成の start）にも `byStartX/Y` へ戻るワープを置く（番外編では「途中で帰る」出口＝`CHALLENGELEAVE_RETIRE`・記録なし。入った時はこのマスに立つが、ワープで着いただけでは乗ったことにならないので、一度離れて戻ると帰れる）。`byGoalX/Y`（中の行き先）は生成の start を入れる。
  5. マップにいる全員へ、データ API の tiles/set と同じ関数（`ResendMapToPlayers`）でマップを送り直す。
  - 範囲が狭い・テーマが無い・生成に失敗した時は、今までの作り方（旧方式）で作る。`dwThemeID` が 0 の時は何も変わらない。
- 中のマップ名: 探索マップ用の情報（`CMD_DUNGEONMAP`）の `szName` にテーマの `name`（日替わりは「（今日のダンジョン）」付き）を入れて送る。クライアントはダンジョンの範囲の中にいる間、マップ名の表示（入った時に画面の真ん中に出る文字）をこの名前にし、範囲に入った時にも出す。マップのデータの名前は変えない。
- 暗さ: テーマの `dark` が 1 以上なら、作る時にマップの明るさレベル（`byLightLevel`）を `dark` にし、暗くする範囲（`aDarkArea`）をダンジョンの範囲 1 つ（`MAPDARK_DARK`）にする。暗くする範囲があると範囲の外は明るいので、同じマップに置いた外の入口は明るいまま。0 ならマップの設定をそのまま使う。
- 扉: テーマに `doorOpen` があれば、扉（`links[].type` 2）のマスごとに扉イベント（`EVENTTYPE_DOOR`。開け閉めは S キー／扉コマンド）を置く。閉じた絵（`wGrpID`）はそのマスの絵（`door`）、開いた絵（`wBackGrpID`）は `doorOpen`。閉まるまでは 3 秒（`byTimeClose` 30）、種別は鍵なし。マスの絵（マップの `pwMap`）は閉じたまま。`doorOpen` が 0 なら置かない（通れる出入口のまま）。
  - 横の壁の扉は 2 行抜くが、扉にするのは下の側面の行だけ（上の天井の行は出入口の床）。
  - 扉の出入口パターン（`openings`）は、パターンの `cellsOpen` があればその絵を開いた絵にする（天井の行は `cellsOpen` で絵が変わる時だけ扉。`cellsOpen` が無ければ下の行だけ `doorOpen`）。

  "parts": [ /* w*h 個のパーツ番号（テーマが無ければ空配列） */ ],

- `rooms[].kind`: 0 ふつう、1 ボス部屋（入口から一番遠い部屋）、2 入口の部屋。`tpl` は使った 9分割の部屋（固定パターンならそのパターン）の番号（-1 = 素の絵）。`fixed` は固定パターンなら 1。

入力の JSON は `{"params": {...}, "theme": {...}}`（theme は省略可）。

## 探索マップ（オートマップ）

テーマで作った気まぐれダンジョン（サブゲーム「ダンジョン」の `dwThemeID` が 0 でない）の範囲の中だけで使う。普段のマップ・旧方式（`dwThemeID` 0）・迷路には出さない。

### 見せる範囲（記録）

- 部屋単位＋見えたマス:
  - 部屋の中（外枠 `rooms[]` の中。出入口の穴の上は除く）に立つと、その部屋の外枠（壁を含む）と、その部屋につながる出入口（`links[]`）を、まとめて記録する。壁ごと抜いた（type 3）出入口でつながった部屋は同じグループにして、いっしょに開ける。
  - それとは別に、見えたマスも記録する。暗いマップ（暗闇・明るさレベル・見える範囲のどれかが効く所）は、灯りの計算で見えたマス（クライアントの `g_pMapDarkTmp` が 1 より大きいマス）。暗くないマップは、画面に見えている範囲（自分から ±7 マス）。
  - 洞窟（L3）のように部屋の一覧がほとんど無いテーマでは、見えたマスだけで地図ができる。
- 記録はクライアントだけが持つ（サーバーには送らない・保存しない）。サーバーは部屋・出入口の一覧を送るだけ。
- 消す条件（ずれ防止）: ①作り直し番号（`dwBuildNo`）が覚えているものと違う（マップ番号・範囲が違う場合も）②ダンジョンの範囲から出た（出口のワープ・死んで戻された時など。入り直したら最初から）③別のマップへ移った④ログアウト・切断・ログイン画面へ戻った。同じ作り直し番号の送り直し（マップの書き込みなど）では消さない。

### 通信（CMD_DUNGEONMAP、サーバー→クライアントだけ）

`CMDPARA_DUNGEONMAP`（`common/TypedefCommon.h`）に、`byValid`・マップ ID・作り直し番号・範囲の四角（マップ座標）・部屋の数・出入口の数が入り、その後ろに部屋 `DUNGEONMAPROOM`（外枠の x,y,w,h とグループ番号）と出入口 `DUNGEONMAPLINK`（つながる部屋 2 つ、穴の範囲、種類 1 アーチ / 2 扉 / 3 壁ごと抜いた）が続く。座標は全部マップ座標（生成の座標＋範囲の左上）。`byValid` 0 は「使わない」（クライアントは地図を全部消す）。

- 作り直した時（`MakeDungeonByTheme`）に、送るままの形で `SUBGAME_DUNGEONINFO` の `pbyAutoMap` に持つ（実行中だけ・保存しない。サーバーを止めると消え、次の作り直しまで地図は出ない）。
- 送るのは、マップ情報（CMD_MAPINFO）を送った直後（そのマップに入った時と、作り直しの `ResendMapToPlayers`。マップ情報でクライアントが地図を消すので直後に送る）。そのマップにダンジョンがある時だけ送る。テーマ方式でない・まだ作っていない時は `byValid` 0 を送る。ダンジョンの無いマップには何も送らない。
- テーマ番号があっても今までの作り方に切り替わった（テーマが見つからない・範囲が狭い）時は、持っていた情報を捨てて、マップにいる全員へ `byValid` 0 を送る。

### 表示

- PC は M キーで出し入れ。Tab の「表示」の切り替え（なし→名前→HP→名前とHP）は、ダンジョンの範囲の中では最後に「地図（名前とHPも出したまま）」が足され、もう一度で「なし」へ戻る（範囲の外では今までどおり 4 つ）。スマホは仮想パッドの「地図」ボタン（M キー。範囲の中にいる時だけ出る。`SboWebGetPadState` の 64）。ブラウザ版は Tab のフォーカス移動をゲーム中の canvas で止めている（`blockKeys` に Tab がある）ので、そのまま使える。
- 画面の真ん中に、範囲が画面の約 75% に収まる倍率で重ねる（ウィンドウより下）。背景を少し暗くし、壁は半透明の線（歩ける記録済みマスと歩けないマスの境目。出入口として出したマスは歩ける扱い）、出入口（アーチ）は緑、扉はだいだい色、自分は赤い点。壁ごと抜いた所は広間なので印は出さない。
- 実装: 記録と線の作り方は `SboCli/src/SboCliAutoMapCore.h`（標準 C++ だけ。単体確認は `tests/client-native/automap.cpp`）、受信・描画・キーは `SboCli/src/SboCliAutoMap.cpp`。サーバーは `SboSvrSubGameProc.cpp`（`MakeDungeonByTheme`）と `SboSvrSendCmd.cpp`（`SendCmdDUNGEONMAP`）。

## ゲームに入れる時の予定: 番外編としての遊び方（2026-11-19 決定）

- 経験値稼ぎの場所にしない。入口で討伐チャレンジと同じくステータステンプレートの姿に入れ替え（ダンジョンごとにテンプレートを決める）、中では経験値・お金は増えない。保存はいつも本物の姿。
- アイテムは手に入る。拾った物はテンプレートの姿の持ち物に入り、中で使える・装備できる（回復手段として）。ただし中だけの物で、どの出方でも外へは持ち帰らない（2026-11-19 決定。周回で物が増えすぎないように。最初は「持ち帰り袋」でゴール時だけ持ち帰る案だった）。クリアのご褒美も今は無し。
- 倒れた時・途中で抜けた時・ゴールした時、どれも元の姿・元の持ち物に戻すだけ。
- 倒れた時は、ふつうの世界と同じく「このまま待つ／帰る」を選べる（仲間が蘇生の特技・道具で起こせば続けられる。「帰る」で元の姿に戻って外へ）。中の全員が倒れたら、もう誰も起こせないので全員まとめて外へ（全滅。ソロは倒れるとすぐ外へ）。倒れた人がいても、残りの人がゴール・全滅させればクリア。
- 何が手に入るかは、ダンジョンの敵・宝箱のドロップの設定で絞る（稼ぎ場にならないように）。
- 役割分担: ダンジョンごとに使えるテンプレートを何種類か登録（職業・レベル・能力・特技・最初の持ち物）。入口に乗ると「どの姿で入りますか？」の一覧から 1 人ずつ選ぶ。テンプレートに職業も持たせる（討伐チャレンジのテンプレートは職業そのまま）。まずは同じ職業の人数制限なし。

## 番外編 段階1 実装方針（2026-11-19）

上の「番外編としての遊び方」の最初の実装。討伐チャレンジの「異空間」の仕組み（空間番号・貸し出し `LoanApply`・`QuestInChallenge` による制限）をそのまま使う。

- 設定（`SUBGAME_DUNGEONINFO`）: `byTmplCount`（0 なら従来どおり）・`wTmplID[8]`・`szTmplName[8][24]`。保存の列は使う時だけ増える（`SboSvrSaveLoadSubGameInfo.cpp`）。データ API の `subGame.detail`（`byTmplCount`・`wTmplID`・`szTmplName1`〜`8`）と管理者ウィンドウのダンジョン編集で直せる。
- 入口: テーマ方式でテンプレートのあるダンジョンの入口（外の入口のマス）に、パーティのリーダー（`adwTblID[0]`。ソロは本人）が乗ると、近くの同じパーティ全員に一覧（`CMD_DUNGEONSEL`）が開く。全員が選ぶ（ソロは選ぶとすぐ）か 30 秒たつと、選んだ人だけで新しい空間へ入る（置いていかれた人にはお知らせ）。リーダー以外が乗った時は入れない。
- 空間: 組ごとに 1 つ（空間番号 = 組の番号）。マップは共有で、敵・扉・敵の数は空間ごと。作り直しは今までどおり誰もいなくなってから（中にいる人は作り直し番号が変わると出る）。全員が出たら敵を消して空間を空きにする（`DgProc`、約 1 秒ごと）。
- 中: テンプレートの姿。経験値・お金は入らない（敵の経験値・お金は 0）。本物の持ち物・預かり所・店・取引・町転送は使えない（討伐チャレンジと同じ制限）。ドロップは中の持ち物へ入る（預かり所へは送らない）。職業は入れ替えない。
- 持ち帰り: しない。出る時は貸し出しの持ち物ごと元に戻す（`DgBagCollect` は中で増えた物を数えるだけで、テスト用）。
- NPC発生の「補充しない（出し切り）」（`byPutOnce`）: 決めた数を出したら補充しない。数えるのは空間ごと（番外編の範囲の中の発生元）。ふつうの世界では起動後・作り直しごとの `byPutDone` で数える。番外編の範囲の中の発生元は、ふつうの世界へは出さず（`DungeonPutIsSpaced`）、組が入った時にその空間へ一度にそろえる。
- 確認: `tests/server/test_main.cpp` の AO。

## 番外編 段階2 実装方針（2026-11-19）

「今日のダンジョン（日替わり）」と最短記録。段階1の番外編（組ごとの空間・テンプレートの姿）の上に足す。

- 作り直しの方式（`SUBGAME_DUNGEONINFO::byRebuildMode`。保存の列は 0 以外の時だけ増える。データ API の `subGame.detail.byRebuildMode`・管理者ウィンドウのダンジョン編集）:
  - 0 = 今まで通り（無人 5 秒で、そのつど新しいシードで作り直す＝気まぐれ）。
  - 1 = 日替わり。サブゲームを 2 件（別の場所）にして、気まぐれと日替わりを並べて遊べる。
- 日替わりのシード: 日付（日本時間 `YYYY-MM-DD`）とダンジョン番号（サブゲームの番号）から決める（`DungeonDailySeed`。FNV-1a）。同じ日なら何度作っても・サーバーを再起動しても同じ形。
- 日付が変わったら: 範囲の中に遊んでいる人（組の空間の中も含む）が誰もいない時に作り直す（周期処理で約 1 秒ごとに見る）。誰かいる間は作り直さず、新しく入る組は前の日の形にそのまま入れる。入口で姿を選ぶ窓を開く時に「日付が変わったので、今の組が出たら新しいダンジョンに作り直します」と知らせる。日替わりでは無人 5 秒の作り直しはしない（形は変わらない）。範囲が無人で 5 秒たった時は、ふつうの世界の NPC発生の「補充しない」の数（`byPutDone`）だけ戻す（扉は自分で閉まる）。サーバーを起動して最初の 1 回は、人がいなくても自動で作る（日替わりは「作成」ボタンを待たない）。
- 管理者の「今すぐ作り直す」: 中の組には知らせてから外へ戻し（`CHALLENGELEAVE_BUILD`）、新しいランダムなシードで作り直す。その日のその後（再起動を含む）はそのシードを使う。管理者ウィンドウのダンジョン編集に「今すぐ作り直す」ボタン（`CMDSUBBOMB_DUNGEONREBUILDNOW`）、データ API は `/api/data/dungeon/rebuild`（書き込みキー）。日替わりのダンジョンだけ。
- 版: 「日付・作り直し番号・シード・テーマの中身の写し・生成器の版番号（`DungeonGen::GEN_VERSION`。形の作り方を変えた時に上げる）・生成設定（範囲の大きさ・テーマ番号）」を 1 つの版として `SBODATA/SboDungeonDaily.json` に保存する（`SboSvrDungeonDaily.cpp`）。
  - テーマの写しは `themes[]` に正規化した JSON で 1 回だけ持ち、同じ内容なら版どうしで使い回す（`themeRef`）。その日の版を作り直す（再起動）時は、ファイルのテーマではなく写しで作る＝その日は形がぶれない。
  - 古い版も残す（将来「過去の版に挑む」用。今回は挑む機能は無い）。版の通し番号 `no` はダンジョンごと。
  - 同じ日に、生成器の版・範囲の大きさ・テーマ番号が変わった時は、同じシード・作り直し番号の新しい版を足す（記録は版ごとなので混ざらない）。
  - 形は `GEN_VERSION` が同じでないと再現できない。上げたら、その日の途中でも次の作り直しで新しい版になる。
- 敵の出方（日替わりだけ）: 番外編の空間への NPC発生は、版のシードと発生元の番号・何回目の試しかを混ぜた `std::mt19937` で位置を決める（`CCharProcPUT::PutOneSpace` の `dwSeed`）。どの組も同じ位置に出る（マスが通れない時の引き直しも、試しの番号が進むだけで順番は同じ）。ドロップの乱数・気まぐれ（方式 0）は今まで通り `genrand`。
- 最短記録: 組が入った時刻（全員そろって `DgStart` した時のサーバーの時計）から、組の誰かが最初にゴールのワープに乗った時までを、その組のクリア時間にする。記録は版ごとに上位 20 件（時間の短い順。同じ時間は先に出した組が上）。1 件に組のキャラ名の一覧・人数・選んだ姿の名前の一覧・時間（ミリ秒）・日時（日本時間）を残す。人数別には分けない。
- 見せ方: ゴールした時に「クリア時間 X分Y秒（今日の○位）」を組の全員に知らせる（20 位より下は「記録の20位には入りませんでした」）。日替わりのダンジョンの入口で姿を選ぶ窓が開く時、今日の 1〜3 位を短いシステムメッセージで知らせる。Web の記録ページは作らない。読み出しはデータ API `/api/data/dungeon/records`（読むだけ。MCP は `sbo_dungeon_records`）。
- クリア条件（`byClearMode`。保存の列は 0 以外の時だけ増える。データ API の `detail.byClearMode`・管理者ウィンドウ）: 0 = ゴールのワープに着く。1 = 敵を全部倒す（その組の空間の、NPC発生の「補充しない」印の敵がなくなった時）。1 でも範囲に補充しない印の発生元が無ければ 0 と同じ。
  - 1 の時は、敵を 1 体倒すたびに組の全員へ「残り N 体」。0 になった瞬間にクリア時間が決まり、「全部倒しました！ クリア時間 X分Y秒（今日の○位）。10秒後に全員戻ります。」と知らせ、3・2・1 を数えて 10 秒後に組の全員（倒れている人も）を `CHALLENGELEAVE_CLEAR` で外へ戻す。それまで途中の判定（倒れた・パーティを抜けた等）はしない。
  - 1 の時のゴールのワープは「途中で帰る」出口（`CHALLENGELEAVE_RETIRE`。「途中で帰りました（記録なし）」）。記録は残さない。
- 記録の人数・名前は、クリアした時まで組に残っていた人（倒れて先に出た人は入れない）。同じ顔ぶれ（キャラのテーブル ID の集合が同じ）の組が同じ版で何度もクリアしても、一番速い記録だけを残す（遅い・同じ時間なら記録は変わらず、今の順位を知らせる）。
- 一発勝負（日替わりだけ）: 順位に入るのは、その版の最初の 1 回だけ。キャラごとに「その版に挑戦した」を覚える（`DGDAILYVER::aTried`。入った＝`DgStart` した時点で使ったことにする。倒れても途中で帰っても 1 回目は使い済み）。保存は `SboDungeonDaily.json` の版の `tried`（挑戦したキャラのテーブル ID の一覧）で、再起動しても残る。組の全員がその版で初めての挑戦の時だけ、クリアで順位の記録に入れる（`CHALLENGE::bRanked`）。1 人でも 2 回目以降の人がいる組は、クリア時間だけ知らせて「今日の挑戦は2回目以降の人がいるので、順位には入りません」と出し、記録には足さない。入口で姿を選ぶ窓が開く時、本人に「今日1回目の挑戦です。クリアすると順位に入ります。」か「今日はもう挑戦したので、今回はタイムだけです（順位には入りません）。」を知らせる。管理者の「今すぐ作り直す」などで版が変われば、新しい版ではまた 1 回目から数える。「同じ顔ぶれは最速だけ」の仕組みは残す。
- 「今日の○位」・記録の保存・入口の上位表示は日替わり（方式 1）だけ。気まぐれ（方式 0）では「クリア時間 X分Y秒」だけ知らせて記録は保存しない。
- 日付を決めるのは `g_tDungeonDailyNow`（0 以外ならそれを今の時刻にする。テスト用）。
- 確認: `tests/server/test_main.cpp` の AP（同じ日付で 2 回作ると同じ形・同じ敵の位置、日付が変わると無人の時だけ作り直す、管理者の作り直し、記録の順位と上位 20 件、版の保存と読み直し、一発勝負＝1 回目の組は入る・2 回目の人が混ざると入らない・作り直しで新しい版はまた 1 回目・読み直しても挑戦済みが残る）と `tools/dungeon/test_gen.sh`（テーマの写しからの再現）。
