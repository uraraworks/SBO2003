# BOT 宣言

人が作ったプログラム（BOT）が、自分は BOT だとサーバーに伝えるための仕組みです。
宣言した接続のキャラは「BOT」として数えられ、オンライン人数とは別に集計されます。
**プレイヤーとしてできることは何も変わりません**（戦闘・移動・お店・取引・発言の制限・速度の制限は通常のまま）。

## 接続の流れ

1. 通常のクライアントと同じように接続し、`CMD_LOGINREQ` でログインする（ログイン応答でキャラが決まる）。
2. **ゲームに入る前**に `CMD_BOTDECLARE` を 1 回送る。
3. 通常どおり `CMD_CHGSTATE` で入場する。このときサーバーは BOT かどうかで人数の入れ先を振り分ける。
4. ログアウト・切断で BOT の扱いは消える。次にログインした時は、また宣言が要る。

1 アカウントの複数接続は、これまでどおり断られます。

## CMD_BOTDECLARE の形式

- 名前は `common/TypedefCommon.h` の `CMD_BOTDECLARE`（`CMD_` の列挙の末尾、`CMD_MAX` の直前。既存の番号はずれない）。
- 中身は `CMDPARA_BOTDECLARE`（クライアント→サーバーのみ。公式クライアントは送らない）。

| オフセット | 大きさ | 内容 |
|---|---|---|
| 0 | 1 バイト | `byCmd` = `CMD_BOTDECLARE` の値 |

全体で 1 バイトです。ほかのコマンドと同じ通信の枠（長さ・CRC・圧縮）に載せます。
誰が送ったかは接続で決まるので、キャラの番号などは入れません（入れても見ません）。
管理者用コマンドの判定（`CMD_MAPPARTSADD` 以上）からは外してあるので、ふつうのアカウントでも通ります。

## 宣言のタイミング

- ゲームに入る前（`byGameState` が `GAMESTATE_MOVE` 未満）の宣言だけ受け付ける。
- ゲームに入った後（`GAMESTATE_MOVE` 以上）の宣言は、返事もなく無視する。
- 一度宣言したら戻せない（取り消すコマンドは無い）。同じ宣言をもう一度送っても何も変わらない。
- NPC には効かない。

## 人数の扱い

- BOT はオンライン人数 `g_dwOnline` に数えず、別の `g_dwBotOnline` に数える。入る時とログアウト時の両方で、BOT かどうかで振り分ける。
- 時間ごとの最大人数・「オンライン数が 10 人になりました」のお知らせ・ゲーム内の人数表示（`CMD_ONLINE`）は BOT を含まない人数。
- **満員の判定（`MAX_CONNECTCOUNT`＝500）は BOT を含む**（`g_dwOnline + g_dwBotOnline`）。
  理由: ログインの時点では BOT かどうかまだ分からず、BOT が多くても実際の接続数・サーバーの負荷は同じなので、含めるほうが安全。
- 状況の API では次のようになる（既存のキーは変えず、追加だけ）。
  - `/health` … `onlinePlayers`（BOT を除く）に加えて `bots`
  - `/api/status` … `onlinePlayers`（BOT を除く）に加えて `bots`
  - `/status` ページ … 「定員 500 人」の横に「BOT n体」を小さく添える
  - 管理ページのオンライン一覧（`/api/admin/online`）… `online`（BOT を除く）に加えて `bots`。各プレイヤーに `bot`（true/false）

## 保存・内部

- BOT のしるしは `CHARINFO::byBot`（サーバーだけ。クライアントへ送る構造体は変えず、保存ファイルにも書かない）。
- 確認は `tests/server/test_main.cpp` の「AZ. BotDeclare」（宣言→入場で `g_dwBotOnline` だけ増える・入場後の宣言は無視・切断で戻る）。
